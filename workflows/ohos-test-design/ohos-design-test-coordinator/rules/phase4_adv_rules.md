# 阶段4对抗：测试用例对抗评估规则

## NEVER（执行约束）

### 数据真实性类
- NEVER 脱离脚本校验结果虚构覆盖率数据——必须调用脚本获取准确数据
- NEVER 脱离test_cases.md虚构重复检测结果——必须基于三次并行Agent真实检测
- NEVER 脱离test_cases.md虚构质量评分数据——必须基于实际用例内容

### 循环对抗类
- NEVER 任一指标不达标时跳过循环对抗——必须循环补充（最多3轮）
- NEVER 超过3轮对抗循环——最多3轮，不达标则强制终止

### 补充生成类
- NEVER 脱离test_point_design.md生成补充测试用例——补充用例必须基于遗漏项
- NEVER 补充测试用例编号使用TC-ADD格式——直接追加到test_cases.md的补充用例必须使用TC-{NNN}顺延编号（批次临时格式TC-{主单元编号}-{序号}仅用于batch文件，合并脚本统一重编号为TC-001~TC-N）
- NEVER 补旧时覆盖用例原来源的 spec/经验库段——只能追加"对抗:"段，保留原 spec+经验库 段
- NEVER 生新前不查同意图已有用例——必须先确认无同意图用例，避免重复（来源不同·意图相同由语义去重合并）
- NEVER 补充用例违反验证完整性原则——预期结果必须验证到外部可观测效果
- NEVER 补充用例出现内部追溯ID——用例名称、预置条件、测试步骤、预期结果必须使用自然语言描述

### 检测类
- NEVER 跳过重复用例检测——充分性达标后必须执行
- NEVER 跳过质量检查——重复检测完成后必须执行
- NEVER 生成资料测试用例——资料测试用例由脚本自动生成，对抗模型不处理

## 执行规则

### 基础数据（由脚本提供）

脚本自动计算：
- 测试用例总数、测试点总数
- 测试点覆盖率
- 关键测试点覆盖率
- 重复用例精确检测（相似度≥95%）
- 质量评分数据准备

### 降级机制

脚本失败 → Agent自行统计基础数据（需明确标注"脚本失败，人工统计"）

## AI判断规则

### 重复用例语义判断与自动处理

对脚本输出的potential_duplicates（相似度≥80%）以及**脚本输出的同测试点多用例检测结果**，AI进行语义判断并自动合并删除：

#### 第一类：文本相似度检测（脚本输出potential_duplicates）

| 重复类型 | 判断标准 | 处理方式 |
|------|---------|---------|
| 完全相同 | 执行方式相同 + 预置条件相似度≥95% + 步骤相同 | 自动删除被合并用例，来源列标注"合并自TC-XXX(对抗模型)" |
| 逻辑等价 | 测试意图相同（验证目标一致） + 预期结果验证点一致 + 仅参数值不同 | 自动删除被合并用例，来源列标注"合并自TC-XXX(对抗模型)" |
| 子集包含 | 执行方式相同 + 测试场景A验证点在B中存在 | 合并为完整用例，删除子集用例，来源列标注"合并自TC-XXX(对抗模型)" |
| 不同来源验证同一行为 | 来源不同（如"对抗"与"spec"段） + 测试意图相同 + 步骤高度相似（≥80%） | 合并为一（保留 spec 用例），来源取并集（spec+经验库+对抗 段）；删除被合并用例 |

#### 第二类：同测试点多用例检测（脚本输出same_tp_multi_cases）

脚本自动检测关联同一测试点且有相同执行方式的多个用例。AI对这些用例进行语义判断：

| 重复类型 | 判断标准 | 处理方式 |
|------|---------|---------|
| 同触发场景 | 关联同一TP + 执行方式相同 + 预置条件核心要素相同 | 合并为1个用例：将所有验证点作为不同步骤合并到保留用例中，删除其余用例 |
| 子集用例 | 关联同一TP + 执行方式相同 + 一个用例的验证点完全被另一个包含 | 删除子集用例，保留完整用例 |
| 合法多用例 | 关联同一TP + 执行方式相同 + 有明确差异化维度（输入值不同、路径类型不同等），各用例验证目标不重叠 | 保留两者，用例名称明确标注差异化维度 |

**合并删除执行**：
- 完全相同/逻辑等价：直接删除重复用例，来源列标注合并来源（如"合并自TC-XXX,TC-YYY"）
- 子集包含：将子集用例的测试步骤、预期结果合并到父集用例，删除子集用例，来源列标注合并来源
- 同触发场景合并：将同触发场景多个用例的验证步骤合并到1个用例（功能验证步骤 + 日志验证步骤 + 访问验证步骤依次排列），删除被合并用例

**逻辑等价判定示例**：
- TC-095/096/097/098：测试意图均为"验证权限为2750"，预期结果均为"目录权限为2750"，仅用例名称不同 → 逻辑等价，保留1个删除3个
- TC-031/032：bundleName超长测试，一个验证"不崩溃"，一个验证"资源状态"，测试意图不同 → 非逻辑等价，保留两者

**非重复判定**：
- 同一测试点的不同边界值（测试意图不同）
- 同一测试点的正常路径和异常路径

### 质量评分

| 维度 | 满分 | 评分规则 |
|------|------|---------|
| 步骤清晰性 | 10分 | 步骤清晰→10分；步骤模糊→5分；不可执行→0分 |
| 预期明确性 | 10分 | 预期明确→10分；预期含糊→5分；预期缺失→0分 |
| 验证完整性 | 扣分项 | 仅依赖"接口返回成功"→扣5分 |

**阈值**：平均质量评分≥18分达标

## 循环对抗规则

若测试点覆盖率或关键测试点覆盖率不达标：

**步骤1：获取当前编号范围**
- Read `{输出目录}/test_cases.md`
- 提取当前最大编号（如最后一个用例为TC-100，则最大编号=100）
- 补充用例起始编号 = 最大编号 + 1

**步骤2：补充用例（补旧优先，二选一或并行）**

- **策略A 补旧（优先）**：对已有相关用例用 Edit 增强充分性——补步骤/预期、子集→并集；在该用例来源末尾追加 `对抗: {补充说明}` 段（保留原 spec+经验库 段）；不新增编号
- **策略B 生新**：遗漏项无相关已有用例时，生成新补充用例；编号规则 TC-{NNN}（顺延，如TC-101~TC-110）；来源 `spec: {..} ｜ 经验库: TE-..,CR-.. ｜ 对抗: {说明}`
- 两策略均需基于 test_point_design.md 遗漏项，格式与 test_cases.md 一致

**步骤3：追加更新test_cases.md**
- 更新头部元信息：`测试用例总数：{原总数}个` → `测试用例总数：{原总数+补充数}个`
- 追加汇总表行：每个补充用例追加1行到汇总表末尾
- 追加详细用例章节：每个补充用例完整格式追加到"详细用例"章节末尾
- 使用Edit工具追加，禁止Write覆盖

**步骤4：重新校验**
- 再次调用phase4_adversary.py脚本校验覆盖率
- 若仍不达标 → 继续下一轮对抗

**循环规则**：
- 最多3轮对抗
- 编号规则：TC-{NNN}（顺延，禁止TC-ADD）
- 每轮重新计算
- 每轮补充后更新编号范围（上一轮最大编号+1）

**时序（强制执行）**：先完成对抗补充（步骤1-4，补旧/生新），**再**执行"AI判断规则"的语义去重——对全部用例（含对抗产生的）按"来源不同·意图相同→合并"处理，合并时来源取并集（spec+经验库+对抗 段并集）。脚本精确去重可在对抗前预筛，语义去重必须在对抗之后。

**追加机制**：

## 补充测试用例生成规则

**生成原则**：
- **NEVER生成"对抗模型"来源的补充用例，除非是以下情况**：
  - 测试点遗漏：phase2已生成测试点，但phase4未生成对应用例
  - 测试点补充：phase2对抗评估补充的TP-ADD-XXX测试点，phase4未生成对应用例
  - 变异存活：phase2定义的变异体未被杀死
- 补充用例明确标注关联测试点（TP-ADD-XXX）
- 编号规则：TC-{NNN}（顺延现有编号）
- 保持与现有测试用例格式一致
- 验证完整性：预期结果必须验证到外部可观测效果
- 内部ID隔离：用例内容使用自然语言，内部ID仅在"关联测试点"列出现
- **NEVER为"当前需求规格"来源的测试点生成"对抗模型"来源的补充用例**：
  - 若测试点来源是"当前需求规格"，补充用例来源也必须是"当前需求规格"
  - 仅当测试点来源是"对抗模型"时，补充用例来源才标注为"对抗模型"

**汇总表追加格式**（追加到汇总表末尾）：
```
| TC-{NNN} | 补充用例名称 | 功能测试 | [等价类/边界值/异常测试/状态转换] | [XTS/黑盒自动化/API性能自动化/手工] | [P0/P1/P2] | 对抗模型 | [TP-XXX] |
```

**详细用例追加格式**（追加到"详细用例"章节末尾）：
```markdown
### TC-{NNN}-补充用例名称

**测试类型：** 功能测试
**测试技术：** [等价类/边界值/异常测试/状态转换]
**执行方式：** [XTS/黑盒自动化/API性能自动化/手工]
**用例级别：** [P0/P1/P2]
**来源：** 对抗模型
**关联测试点：** [TP-XXX]

**预置条件：**
- [预置条件列表]

**测试步骤：**
| 步骤 | 操作（含数据） | 预期结果 |
| --- | ------------ | -------- |
| 1 | [操作] | [预期结果] |
```

**追加注意事项**：
- 追加汇总表行时，定位到汇总表最后一行（`| TC-XXX |`）后插入新行
- 追加详细用例时，定位到最后一个详细用例章节后插入新章节
- 保持与test_cases.md现有格式完全一致（换行、缩进、表格分隔线）
