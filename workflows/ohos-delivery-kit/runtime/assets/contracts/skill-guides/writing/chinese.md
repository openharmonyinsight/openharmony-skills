# 中文交付文档写作规则

生成或修订中文 proposal、spec、design、plan、验证说明和审查报告时，执行本规则。
用户指定其他语言时，遵循用户要求。项目已有术语表或专项用语规范时，沿用其中的术语。
只检查本次需要撰写或修改的内容，不为统一文风批量改写历史文档，也不刷新未受影响的 spec。
桥接时仅约束 ODK 负责撰写或修改的中文内容；透传模式保留原文，不为润色改写源插件工作区。

## 必须遵守

1. **用中文说明具体事情。** 写明什么条件下，谁执行什么操作，会出现什么结果。
   不把英文短语逐词压缩成中文名词串；“范围、条件、结果、占用的内存”等常用说法足够时，
   不另造“等价域、收益面、资源档位”等简称。已有准确的专业术语可以保留，读者不易理解时首次解释。
2. **一句话表达一个主要要求。** 条件、结果、例外分别说明；多种设备、配置或屏幕条件用表格对照。
   AC 保留 Given/When/Then 格式，三部分的描述使用中文。复杂适用条件可引用已定义的范围或表格，
   不把整张条件表、计算过程和测试状态塞进同一条 AC。
3. **同一概念使用同一名称。** 首次写清含义，再使用明确的简称。
   不在相邻段落把同一对象交替称为“图元、字形、图形、墨迹”，除非它们确实表示不同对象并已说明区别。
   不把“契约、边界、收敛、闭环”等词当作省略具体要求的替代品；这些词有明确技术含义时可以使用。
   同一个词要结合上下文理解：“落盘”可能指保存证据文件，也可能涉及数据持久化；“门禁”不一定是权限检查。
4. **技术标识与固定格式保持原样。** 不翻译 API、参数名、路径、错误码、枚举值、机器读取的字段或状态值。
   保留固定章节名、表头、G/US/AC/BR/EX/Task 编号及 Given/When/Then 标记。
   正文中的一般描述优先用中文，例如“默认未配置”“等比例缩小”，不必机械地混用英文。
5. **润色不能改变需求。** 保留所有适用条件、否定、例外、比较基线、数值、单位与“待确认”状态。
   写清“减少了多少”和“降至原来的多少”；不能把图像数据占用的内存写成整个进程的常驻内存，
   也不能把理论计算、目标值或历史结果写成本次实测结论。原文不清楚时标明待确认，不替用户补决定。

## 对照示例

以下改写仅适用于表中给出的语境，不是全局禁词表，也不是逐词替换规则。
首次撰写或修订中文交付件时，一并阅读[从交付文档归纳的正反例](chinese-examples.md)；
后续按表达问题查阅。例子用于学习句式，不将其中的业务约束、错误码或验证结果移植到其他需求。

| 语境中的原表达 | 建议写法 |
|----------------|----------|
| 显示等价域：dpi ≤ 6.4 | 显示效果须保持不变的适用范围：dpi ≤ 6.4（包含 6.4） |
| dpi > 6.4 时，域外候选行为为等比收敛 | dpi > 6.4 时，待确认的处理方案是等比例缩小图标，使其完整显示 |
| 单屏硬光标像素载荷 | 每块屏幕的硬光标图像像素数据占用的内存 |
| 按屏满足资源目标（前表只约定了内存） | 每块屏幕分别满足前表规定的内存目标 |
| 正常域不误缩 | 在约定的正常显示范围内，不额外缩小图标 |
| 内存收益覆盖面显著缩小 | 能降低内存占用的设备和屏幕场景明显减少 |
| 由约 10 MiB 降至约 2.5 MiB，减少 4 倍 | 由约 10 MiB 降至约 2.5 MiB，降至原来的约 25%，减少约 75% |

AC 示例（沿用原有格式，描述使用中文）：

```markdown
- **AC-2.7:** Given 光标样式、大小和屏幕坐标相同 When 旋转屏幕并比较修改前后的显示结果 Then 光标实际指向的屏幕像素不变，位置偏差为 0 px。
```

这个示例只展示句式。实际 AC 必须带上需求已约定的适用范围，不照搬示例的编号、数值或条件。
显示要求仍写在 spec，内部计算方式写在 design，测试文件、命令和结果写在 plan/evidence。

## 输出前逐项检查

- 读者是否能直接说出适用条件、操作和结果？将只能靠猜测理解的简称或名词串展开为中文句子。
- 同一对象是否前后一致？通用表达是否混入了不必要的英文？代码标识和项目正式术语是否保持原样？
- 与输入逐项对照：范围、阈值、单位、否定、例外、批准/待确认状态是否完整保留？
- 是否为简化句子而删除了验收要求，或把实现细节重新塞回 spec？有问题时修改对应段落后再检查。

这是写作与语义自检要求，不新增归档审批，也不代表结构校验器能判断中文是否自然。
