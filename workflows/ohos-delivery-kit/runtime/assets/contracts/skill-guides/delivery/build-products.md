# 编译产品选择

先读取已有执行计划并判断验证范围。若所有 Task 均为仓库内主机测试、文档或配置检查，
且不编译目标产品、不依赖设备/模拟器，在环境表记录 `验证范围=host-only` 和实际命令，
跳过本指南中的产品/设备选择。只要任何 Task 需要目标编译或设备，本指南仍完整适用。

`build_products` 是供用户选择的产品列表，采用空格分隔的字符串，和现有配置中的
技能列表、目录列表格式一致。`build_product` 仅标注菜单默认项，**配置值不等于用户选择**。
一次计划选择一个产品，选择前不生成该产品的编译命令，不自动逐个编译全部产品。

运行 using-odk 定义的配置命令，按 [配置规则](../router/configuration.md) 使用返回的 `config`；同目录用户配置按 key 覆盖默认值，不在本指南中重新读写安装目录配置。
扩展文件中的 `build_products` 替换整个列表，不与默认列表拼接。按空白拆分，保留顺序，
去除重复产品名；不要将它解析为 YAML 数组。

- 未提供 `build_products` 的旧配置：使用非空 `build_product` 作为单项列表。
- 显式配置空列表：提示用户补充产品，不能继续使用写死的备选项。
- 默认产品不在列表中：显示“当前列表无默认项”，请用户选择列表中的产品；不自动追加
  默认产品，也不悄悄选第一个。

在 plan 开始时运行配置加载器的 `--build-product-options`，使用返回的 `products`、
`default_product` 和 `menu` 展示选择。`selected_product: null` 和
`confirmation_required: true` 表示仅由配置不能得到已确认选择；不能把默认项复制成已选项。
该命令只读配置，不写计划、不执行编译。原生/中立包使用
`python3 runtime/executables/lib/odk_repository.py --build-product-options`，源码使用
`python3 scripts/lib/odk_repository.py --build-product-options`。

按实际列表生成编号菜单，标注默认项，**展示后等待用户回答**。例如：

```text
本次计划使用哪个编译产品？
1) a（配置默认项）
2) b
请回复序号、产品名，或明确回复“使用默认产品”。
```

示例菜单中的名字必须替换为实际返回值。只有用户明确输入序号、产品名，或针对
本次产品选择明确确认默认项，才获得选择。用户已为本次计划明确选定具体产品时
直接复用，不重复提问。写过配置、开启自主模式、泛称“自动/全选推荐/继续”、没有
回答或仅存在一个候选，都不能替代产品选择。缺少明确选择时停在这里，保留待选状态，
不写环境表、不解析 `{product}`，不进入编译或实现。

列表之外的产品须让用户明确确认作为本次新增选项，随后更新计划中的列表；
不要自动修改配置文件。

将去重后的完整列表写入 `execution-plan.md` 的 `可选编译产品` 行，将最终选择写入
`编译产品` 行；在 `产品选择确认` 行记录用户实际答复的摘要，不得把“配置默认值”
写成确认依据。该表是这次计划的快照：实现阶段复用已确认选择，不因配置后来变化而
静默切换产品。已有 `编译产品` 或编译命令本身不能证明用户曾选择该产品。
旧计划缺少确认记录时，能追溯到用户针对该产品的明确答复则补入记录并沿用；否则
在首次执行编译命令之前询问一次。不要因旧计划缺少环境表而直接从默认值补全并编译。
用户要求切换时再按当前配置生成菜单并更新快照。

选择后再执行设备版本策略：`arm64_virt` 使用 QEMU，不询问 daily；其他产品询问
daily 或设备现有版本。新增产品名不意味着其自动刷机受到支持。
