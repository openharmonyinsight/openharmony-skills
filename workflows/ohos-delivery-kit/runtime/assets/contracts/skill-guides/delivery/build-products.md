# 编译产品选择

`build_products` 是供用户选择的产品列表，采用空格分隔的字符串，和现有配置中的
技能列表、目录列表格式一致。`build_product` 保留为默认产品；一次计划选择一个产品，
不是自动逐个编译列表中的全部产品。

从同目录的 `odk_config.yaml` 和 `odk_config_ext.yaml` 读取配置，后者按 key 覆盖前者。
扩展文件中的 `build_products` 替换整个列表，不与默认列表拼接。按空白拆分，保留顺序，
去除重复产品名；不要将它解析为 YAML 数组。

- 未提供 `build_products` 的旧配置：使用非空 `build_product` 作为单项列表。
- 显式配置空列表：提示用户补充产品，不能继续使用写死的备选项。
- 默认产品不在列表中：显示“当前列表无默认项”，请用户选择列表中的产品；不自动追加
  默认产品，也不悄悄选第一个。

按实际列表生成编号菜单，标注其中的默认项。接受用户明确确认默认项、输入序号或完整
产品名。无回答不表示确认。列表之外的产品须让用户明确确认作为本次新增选项，随后
更新计划中的列表；不要自动修改配置文件。

将去重后的完整列表写入 `execution-plan.md` 的 `可选编译产品` 行，将最终选择写入
`编译产品` 行。该表是这次计划的快照：实现阶段复用选择与列表，不因配置后来变化
而静默切换产品。旧计划缺少列表但已有选定产品时补入该产品，不需要重问已确认的选择；
用户要求切换时再按当前配置生成菜单并更新快照。

选择后再执行设备版本策略：`arm64_virt` 使用 QEMU，不询问 daily；其他产品询问
daily 或设备现有版本。新增产品名不意味着其自动刷机受到支持。
