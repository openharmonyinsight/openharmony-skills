# 计划阶段的设备版本选择

在确认编译产品名、验证范围和验证产品后、生成计划前执行。将选择写入
`execution-plan.md` 的 `## 构建与验证环境`，供实现阶段直接读取。
编译名可以具体或抽象，不能用它判断设备版本策略。复用当前验证目标已有的实际确认；
验证产品或实际设备变更时重新判断，不能沿用其他目标的准备结果。

- **host-only / build-only**：不进入设备版本选择；build-only 的两行均填 `N/A`。
- **emulator**：不询问 daily，不下载或刷入物理板镜像。两行均填 `不适用（模拟器）`，
  已有 QEMU 记录可保留 `不适用（QEMU）`；按独立确认的验证产品启动模拟器。
- **device**：先确认具体 `验证产品`，无论是否配置自动刷机 skill，都询问并等待明确回答：

  ```text
  当前编译产品：<具体或抽象编译名>
  当前验证产品：<已确认具体设备产品>
  测试设备使用哪个版本？
  A) 获取 daily 版本，准备好设备后验证
  B) 使用设备上已有的版本
  ```

  不把无回答当作 B，不因缺少刷机 skill 而隐藏 A。
  - 选择 A：`设备版本策略` 填 `daily`。仅当验证产品为 `rk3568` 且配置了
    `device_flash_skill` 时，可将具体 skill 名写入 `设备版本准备方式`。
    编译产品是否为 `rk3568` 不参与该判断。其他情况向用户确认适用的镜像来源与手动准备步骤，写入该行；不能执行的准备步骤
    应记录为阻塞，不得静默改成使用现有版本或调用不支持该产品的 skill。
  - 选择 B：`设备版本策略` 填 `existing`，`设备版本准备方式` 填
    `使用设备现有版本，不获取 daily、不刷机`。

计划阶段只确认策略，不执行下载或刷机。批准计划中的 daily 选择不代表授权覆盖
任意设备数据：实现阶段仍须选定目标设备，并在刷机前明确确认覆盖操作。
计划阶段也不安装刷机 skill。实现阶段满足上述自动刷机条件、选定设备并确认覆盖后，
调用前按 [configured-skills.md](../router/configured-skills.md) 检查当前 Agent 的 skill；
缺失时从该参数上方注释的安装链接安装并确认可用，再执行刷机。安装成功不能代替
设备准备成功的证据；等待重启或安装失败时保留待执行步骤。

旧计划缺少验证范围、验证产品、验证目标确认或版本两行时，在首次运行验证前补齐；
不得从编译名推断目标。实现阶段复用已记录的策略；
版本准备成功后在 Task `Actual Result` 记录设备与结果，同一设备沿用该准备结果，
不在每个 Task 或最终集成验证重新获取 daily。设备更换或用户要求变更版本时，
先更新计划再准备设备。`existing` 不表示设备已经是今日 daily，不得这样报告。
