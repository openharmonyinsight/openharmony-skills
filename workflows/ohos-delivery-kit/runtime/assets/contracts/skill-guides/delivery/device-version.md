# 计划阶段的设备版本选择

在确认编译产品后、生成计划前执行。将选择写入 `execution-plan.md` 的
`## 构建与验证环境`，供实现阶段直接读取。用户已为当前产品明确选择时复用，
不重复询问；切换产品后重新判断。

- **QEMU（`arm64_virt`）**：不询问是否获取 daily，不下载或刷入物理板 daily。
  `设备版本策略` 和 `设备版本准备方式` 均填 `不适用（QEMU）`，按模拟器命令验证。
- **其他产品**：无论是否配置自动刷机 skill，都询问并等待明确回答：

  ```text
  当前编译产品：<已确认产品>
  测试设备使用哪个版本？
  A) 获取 daily 版本，准备好设备后验证
  B) 使用设备上已有的版本
  ```

  不把无回答当作 B，不因缺少刷机 skill 而隐藏 A。
  - 选择 A：`设备版本策略` 填 `daily`。仅当产品为 `rk3568` 且配置了
    `device_flash_skill` 时，可将具体 skill 名写入 `设备版本准备方式`。
    其他情况向用户确认适用的镜像来源与手动准备步骤，写入该行；不能执行的准备步骤
    应记录为阻塞，不得静默改成使用现有版本或调用不支持该产品的 skill。
  - 选择 B：`设备版本策略` 填 `existing`，`设备版本准备方式` 填
    `使用设备现有版本，不获取 daily、不刷机`。

计划阶段只确认策略，不执行下载或刷机。批准计划中的 daily 选择不代表授权覆盖
任意设备数据：实现阶段仍须选定目标设备，并在刷机前明确确认覆盖操作。

旧计划缺少这两行时，在首次设备验证前按上述规则补齐。实现阶段复用已记录的策略；
版本准备成功后在 Task `Actual Result` 记录设备与结果，同一设备沿用该准备结果，
不在每个 Task 或最终集成验证重新获取 daily。设备更换或用户要求变更版本时，
先更新计划再准备设备。`existing` 不表示设备已经是今日 daily，不得这样报告。
