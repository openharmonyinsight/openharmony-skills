## 影响范围与漏改检查

核对计划文件、实际完整 diff 与相关入口/实现/配置路径，确认应修改点均有改动或有依据的处置。
根据接口、共享状态等具体风险检查相关调用点及未修改代码，不能只检查已修改函数。
记录实际使用的 LSP/AST 或替代检查、范围及局限；只安装了工具、结果为空或索引不完整，
都不能证明路径已经找全。无法从 diff 验证的要求交给协调者核实；发现漏改或必需验证缺口时，
按现有问题闭环流程处理，不以工具不可用为由豁免，也不额外派发重复审查。
