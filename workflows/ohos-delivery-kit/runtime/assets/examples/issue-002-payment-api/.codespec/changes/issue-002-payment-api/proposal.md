# Proposal

## 背景与问题

应用需要集成支付功能，允许用户通过绑定的支付方式完成商品购买。当前系统缺乏支付能力。

## 初始分级判断

| 判断项 | 结果 | 依据 |
|--------|------|------|
| 复杂度 | 复杂 | 涉及跨进程通信、敏感数据、网络交互 |
| 涉及仓数量 | 3 | 应用、支付服务、安全框架 |
| 是否涉及 Public/System API | 是 | 新增支付 SDK API |
| 是否涉及安全/性能关键路径 | 是 | 处理支付凭证、金融数据 |
| 是否跨 SIG | 是 | 涉及多个 SIG |

## 目标

新增支付 SDK API，支持应用安全地调用支付服务完成支付流程。

## 非目标

- 不处理退款流程（由独立变更覆盖）
- 不处理支付方式管理（由独立变更覆盖）

## Agent Scope Guard

> 约束 AI/Agent 的探索和修改边界。若需要突破边界，先更新本 proposal 并获得确认。

| 维度 | 范围/限制 | 需人工确认的触发条件 |
|------|-----------|----------------------|
| 允许仓库 | payment, security | 需要修改应用仓库或新增第三方仓库 |
| 允许模块/目录 | payment/sdk/, payment/service/binder/, security/tee/keystore | 需要触碰非支付/安全框架模块 |
| 禁止修改项 | TEE 固件、KeyMint TA、既有支付方式管理逻辑、退款流程 | 需要变更可信固件或现有支付方式数据结构 |
| 外部依赖/网络访问 | 仅依赖系统 TEE/KeyMint，不引入第三方支付 SDK；支付网关走系统网络栈 | 需要引入三方库或新增外网端点 |

## 成功标准

| 标准 | 可观察指标 | 验证方式 |
|------|-----------|---------|
| 支付 API 可用 | 应用可成功调用支付接口 | 集成测试 |
| 敏感数据保护 | 支付凭证加密传输 | 安全扫描 |
| 跨进程通信安全 | Binder IPC 有权限检查 | 安全审计 |

## 影响范围

| 子系统 | 仓库 | 模块/路径 | 影响类型 |
|--------|------|-----------|---------|
| Payment Framework | payment | sdk/payment_api.h | 新增 |
| Payment Service | payment | service/binder/service.cpp | 变更 |
| Security Framework | security | tee/keystore | 依赖 |

## 假设与开放问题

### 假设
- 设备支持 TEE（可信执行环境）
- 支付凭证已通过 KeyMint 保护

### 开放问题
- 支付服务的高可用性方案（需后续设计）
- 支付失败的重试策略（需后续设计）

## 不涉及项确认

| 维度 | 是否涉及 | 依据 |
|------|---------|------|
| 性能 | 是 | 支付响应时间 < 500ms |
| 安全/权限 | 是 | 涉及支付凭证、权限申请 |
| 兼容性 | 是 | 新增 Public API |
| API/SDK | 是 | 新增支付 SDK |
| IPC/跨进程 | 是 | 应用 ↔ 支付服务 Binder 通信 |
| 构建/组件 | 否 | 无构建变更 |
| 国际化/无障碍 | 否 | 暂不涉及 |
| 数据迁移 | 否 | 无本地数据存储 |
