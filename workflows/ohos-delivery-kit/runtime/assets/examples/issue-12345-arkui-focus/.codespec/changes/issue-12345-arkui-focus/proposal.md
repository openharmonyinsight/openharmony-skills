# Proposal

## 背景与问题

ArkUI 框架当前缺少统一的焦点管理能力。组件在获得/失去焦点时没有标准回调机制，
开发者需要自行实现焦点跟踪逻辑，导致不一致的行为和重复代码。

## 用户场景与业务触发

### US-1: 组件获焦时更新 UI 高亮
- **角色**：ArkUI 应用开发者 / 终端用户（键盘 Tab 或触屏点击）
- **业务触发**：终端用户按 Tab 遍历或点击组件，开发者声明 `focusable(true)` 的组件获得焦点
- **业务价值**：开发者据获焦/失焦回调更新 UI 高亮，无需自行实现焦点跟踪；可操作动作序列见 spec.md AC-1.1~1.3

### US-2: 业务规则驱动的编程式焦点切换
- **角色**：ArkUI 应用开发者
- **业务触发**：开发者需按业务规则（如表单校验失败自动聚焦输入框）编程式移动焦点
- **业务价值**：业务规则可驱动焦点切换，覆盖表单导航等场景；可操作动作序列见 spec.md AC-2.1~2.3

### US-3: 组件卸载自动清理焦点（系统视角）
- **角色**：系统视角（焦点管理器内部行为）
- **业务触发**：终端用户导航离开页面或组件被条件渲染移除，导致持有焦点的组件卸载
- **业务价值**：防止悬空引用和焦点泄漏，无需开发者手动清理；可观测行为见 spec.md AC-3.1~3.2

## 初始分级判断

> L0/简单变更：非目标、影响范围等章节可简化为一句话；L1+ 建议完整填写所有表格。

| 判断项 | 结果 | 依据 |
|--------|------|------|
| 复杂度 | 标准 | 涉及新模块 + 公开 API 新增 |
| 涉及仓数量 | 2 | frameworks/arkui + interfaces/arkui |
| 是否涉及 Public/System API | 是 | 新增 focusable/onFocus/onBlur/requestFocus ArkTS API |
| 是否涉及安全/性能关键路径 | 否 | 焦点切换为低频操作 |
| 是否跨 SIG | 否 | 仅涉及 arkui SIG |

## 目标

为 ArkUI 组件提供声明式焦点管理 API：
- 组件可声明焦点能力（focusable/focus-in-order/focus-out-order）
- 提供 onFocus/onBlur 回调
- 支持编程式焦点切换（requestFocus）

## 非目标

- 不实现焦点导航算法（方向键导航留待后续）
- 不改变现有组件的默认焦点行为（向后兼容）

## Agent Scope Guard

> 约束 AI/Agent 的探索和修改边界。若需要突破边界，先更新本 proposal 并获得确认。

| 维度 | 范围/限制 | 需人工确认的触发条件 |
|------|-----------|----------------------|
| 允许仓库 | frameworks/arkui, interfaces/arkui | 需要修改其他仓库 |
| 允许模块/目录 | frameworks/arkui/component/focus/, interfaces/arkui/component/ | 需要触碰渲染、事件分发或构建系统 |
| 禁止修改项 | 现有默认焦点行为、方向键导航算法、FocusGroup | 需要改变现有组件默认行为 |
| 外部依赖/网络访问 | 不新增外部依赖，不需要网络访问 | 需要引入三方库或下载资源 |

## 成功标准

> 每条标准必须可观察、可量化。"提升性能"不可验证，"P95 延迟 < 100ms"可验证。

| 标准 | 可观察指标 | 验证方式 |
|------|-----------|---------|
| 组件声明 focusable(true) 后可获得焦点 | 焦点变化可被应用层感知（onFocus 触发） | 集成测试：focusable 组件获焦时 onFocus 触发 |
| 焦点变化时触发对应回调 | 焦点转移时应用层收 onFocus/onBlur | 集成测试：验证回调触发时机 |
| 编程式焦点切换正常工作 | requestFocus() 调用后焦点正确转移 | 集成测试：requestFocus → 目标组件收到 onFocus |
| 默认焦点行为不变 | 未声明 focusable 的组件行为与变更前一致 | 回归测试：现有组件焦点行为无变化 |

## 影响范围

| 子系统 | 仓库 | 模块/路径 | 影响类型 |
|--------|------|-----------|---------|
| arkui | frameworks/arkui | component/focus/ | 新增 focus_manager 模块 |
| arkui | interfaces/arkui | component/ | 新增 ArkTS API |

## 假设与开放问题

### 假设
- Tab 键为默认焦点遍历键，Shift+Tab 反向遍历（沿用平台默认行为）
- 焦点切换不触发组件重建，仅触发 onFocus/onBlur 回调

### 开放问题
- 焦点组（FocusGroup）是否在本次实现？→ 决策：留待后续迭代
- 方向键焦点导航算法复杂度评估？→ 决策：本次不实现

## 不涉及项确认

| 维度 | 是否涉及 | 依据 |
|------|---------|------|
| 性能 | 否 | 焦点切换为低频操作（用户交互驱动），不涉及性能热路径 |
| 安全/权限 | 否 | 无权限相关逻辑，焦点管理为组件内部行为 |
| 兼容性 | 否 | 默认行为不变，纯增量 API。未声明 focusable 的组件行为与之前完全一致 |
| API/SDK | 是 | 新增公开 ArkTS API: focusable()/onFocus()/onBlur()/requestFocus() |
| IPC/跨进程 | 否 | 焦点管理在单进程内，不涉及跨进程通信 |
| 构建/组件 | 否 | 在现有 frameworks/arkui/component/focus/ 目录下新增文件 |
| 国际化/无障碍 | 否 | 焦点行为与语言无关 |
| 数据迁移 | 否 | 无持久化数据，焦点状态为运行时状态 |
