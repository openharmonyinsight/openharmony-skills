# arch：①重复造轮子 / ②性能

只承担这两个维度，其他维度的具体风险交协调者路由，不复制整套审计。

## ① 重复造轮子

- 从新增能力、状态和工具函数出发，用符号/语义搜索寻找仓内相邻层的既有实现；记录搜索
  范围及候选位置。语义工具不可用时用 `rg` 和调用关系，不把工具缺失当作没有既有实现。
- 对照语义、错误处理、线程约束、所有权和层间依赖。名字相似并不足以要求复用；跨层
  反向依赖、额外公共 API 或过度抽象也可能比局部实现代价更高。
- 检查同一事实是否被维护两次：缓存与源状态、重复校验、重复序列化、平行配置和错误码
  映射。指出会在哪个变化下发生偏离，而不是单纯要求减少行数。
- 要求复用时给出实际可用的符号与兼容条件；保持新增实现时说明为何现有能力不适用。

## ② 性能

- 先确定执行频率和输入增长：启动、每帧、IPC 高频、批处理还是冷路径。对无工作负载
  依据的猜测写待确认，不因“可能更快”提出阻塞性重写。
- 沿实际路径比较修改前后：循环内分配/复制/序列化、重复扫描、查询放大、锁内 I/O、
  同步跨进程调用、无界队列/缓存、失败重试与超时累积。区分一次成本与随 n 增长的成本。
- 核对资源寿命和释放是否使开销累积；涉及数据竞争的安全影响交 security，性能影响
  仍在本席记录，最后由协调者按同一根因合并。
- 优先使用已有基准/trace/内存数据。确需测量时给出输入规模、对照基线、指标和可复现
  命令；不把缺少基准、理论复杂度变化或微小分配自动判为 High。

用 task-arch 模板逐维报告；候选项遵守 [发现协议](findings-and-rereview.md)。
没有发现时记录检索过的既有实现和检查过的主要路径，避免空泛“符合最佳实践”。
