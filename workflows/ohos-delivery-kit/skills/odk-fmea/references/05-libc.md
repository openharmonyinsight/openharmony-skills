# libc / libc++ 故障模式

### C-01 内存分配失败未判空
- 典型原因：malloc/strdup 返回值未判空直接解引用；new(nothrow) 误判为抛异常版本。
- 典型影响：低内存场景空指针崩溃（现网高发、本地难复现）。
- 故障注入：注入分配失败（如 mock malloc 返回 nullptr）；内存水位压测。
- 日志/Trace：分配失败日志（多数代码缺失）；faultlog 空指针栈。
- 消减建议：返回值判空+降级路径；低内存监听与缓存释放。

### C-02 缓冲区溢出 / 越界读写
- 典型原因：strcpy/strcat/sprintf 等不检查长度；memcpy 长度来自外部数据未校验；数组下标未检查。
- 典型影响：内存破坏、崩溃、安全漏洞（可执行任意代码）。
- 故障注入：超长输入；fuzz 边界值。
- 日志/Trace：ASAN/HWASAN 报告；faultlog SIGSEGV。
- 消减建议：使用安全函数（snprintf/strlcpy）或 std::string；外部长度字段先校验再使用。

### C-03 use-after-free / double free
- 典型原因：多线程释放与使用竞争；错误路径重复释放；智能指针与裸指针混用。
- 典型影响：偶发崩溃、堆破坏（难定位）。
- 故障注入：ASAN 下跑并发路径。
- 日志/Trace：ASAN heap-use-after-free 报告。
- 消减建议：统一智能指针所有权；释放后置空；并发路径加锁。

### C-04 字符串未以 '\0' 结尾
- 典型原因：strncpy 不保证终止；从网络/文件读入缓冲区直接当 C 字符串。
- 典型影响：越界读、乱码、崩溃。
- 故障注入：构造恰好填满缓冲区的输入。
- 日志/Trace：ASAN 越界读报告。
- 消减建议：写入后显式补 '\0'；优先 std::string。

### C-05 整数溢出
- 典型原因：长度计算（a*b+c）溢出后分配过小缓冲区；size_t 与 int 混用符号转换。
- 典型影响：小分配大拷贝→堆溢出（安全）。
- 故障注入：构造使乘法溢出的超大长度字段。
- 日志/Trace：UBSAN signed-integer-overflow 报告。
- 消减建议：分配前做溢出检查（__builtin_mul_overflow 等）；统一无符号语义。

### C-06 格式化字符串误用
- 典型原因：printf(user_input)；格式串与参数个数/类型不匹配。
- 典型影响：信息泄露、崩溃、安全漏洞。
- 故障注入：输入含 %s/%n 的字符串。
- 日志/Trace：编译告警（-Wformat）；崩溃栈。
- 消减建议：格式串一律字面量；开启编译告警。

### C-07 STL 使用错误
- 典型原因：迭代器失效后继续用（erase/push_back 后）；vector 下标越界用 [] 而非 at；遍历时修改容器。
- 典型影响：偶发崩溃、数据错乱。
- 故障注入：构造触发迭代器失效的操作序列。
- 日志/Trace：ASAN/_GLIBCXX_DEBUG 报告。
- 消减建议：erase 用返回值更新迭代器；边界敏感处用 at。

### C-08 异常跨边界传播
- 典型原因：异常穿过 C 接口/NAPI 边界；noexcept 函数内抛异常。
- 典型影响：std::terminate 直接终止进程。
- 故障注入：在接口实现中注入异常。
- 日志/Trace：terminate 调用栈 faultlog。
- 消减建议：接口边界统一 try-catch 转错误码。

### C-09 errno / 系统调用返回值未检查
- 典型原因：read/write/open/pthread_* 返回值未检查或只判 -1 不判短读短写。
- 典型影响：静默数据错误、半操作被当成功。
- 故障注入：注入系统调用失败/中断（EINTR）。
- 日志/Trace：系统调用失败日志含 errno。
- 消减建议：封装带重试与完整错误处理的 IO 函数。

### C-10 崩溃信号特征（用于故障注入后的日志识别）
- 典型原因：各信号对应典型根因——SIGSEGV（空指针/越界/UAF）、SIGABRT（断言失败/堆破坏检测/未捕获异常）、SIGBUS（对齐错误/mmap 文件被截断）、SIGFPE（除零/整数溢出）、SIGILL（非法指令/函数指针被破坏）、SIGPIPE（向已关闭 socket/pipe 写数据，默认动作杀死进程）、SIGTRAP（断点/__builtin_trap）。
- 典型影响：进程崩溃；栈溢出（递归无出口/超大栈帧）表现为 SIGSEGV 且栈帧重复，栈覆盖表现为返回地址被破坏跳异常地址。
- 故障注入：除零、递归无终止、向已断开的 pipe 写入。
- 日志/Trace：faultlog 的 `Reason:Signal:SIGxxx(...)` + 寄存器 + 调用栈；栈溢出可见大量重复栈帧；SIGPIPE 退出无 crash 栈（需检查是否误忽略）。
- 消减建议：按信号类型反向定位代码模式；SIGPIPE 明确忽略并处理 EPIPE 错误码；递归改迭代或加深度的保护。
