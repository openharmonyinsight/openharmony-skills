# 数据库故障模式

### D-01 数据库打开失败
- 典型原因：db 文件不存在（首次启动路径错误、路径被清理）；权限错误（沙箱与多用户路径错配、SELinux 拒绝、属主变更）；加密密钥丢失（HUKS 异常、密钥被清除）；db 路径被同名目录或其他文件占位。
- 典型影响：依赖数据的功能整体不可用；启动崩溃。
- 故障注入：删除 db 文件；chmod 去除读写权限；删除 HUKS 密钥后启动；把 db 路径替换为同名目录。
- 日志/Trace：RDB store open 失败 errcode 日志；ENOENT/EACCES errno 日志；密钥读取失败日志。
- 消减建议：open 失败按 errcode 分级（可缺省与致命分开处理）；首次运行自动建库；权限失败与密钥缺失分别上报事件；路径一律通过系统接口获取，不硬编码。

### D-01a 数据库文件损坏
- 典型原因（按损坏形态分类，分析时逐类核对）：
  1. **头部与 schema 页损坏**：db 首页（页 1）被破坏，`sqlite_master` 不可读，整库无法被识别。
  2. **页级内容损坏**：部分数据页被覆盖或写入垃圾，表现为能打开但查询报错，按页随机失败。
  3. **WAL / journal 损坏**：预写日志或回滚日志不完整，恢复（recovery）阶段失败，库卡在无法打开状态。掉电是高发场景。
  4. **索引与元数据不一致**：B 树索引与实际行数据不匹配，查询结果漏行或错行且不报错，属静默错误，最易被业务采信。
  5. **文件被截断**：只剩前 N 页，尾部页缺失，长度字段与内容不匹配。
  6. **全零文件**：文件长度正确但内容全为 0，是掉电与存储故障的典型产物，可绕过仅做长度校验的实现。
  7. **文件被替换或密钥不匹配**：db 被同名文件覆盖，或用错误的密钥解密。
- 典型影响：打开失败或按页失败；数据丢失；索引不一致导致查询结果静默错误被业务采信；若损坏发生在 owner 服务侧，表现为该服务全部调用方大面积失败。
- 故障注入：文件注入｜篡改 db 首页头部字节；文件注入｜用 dd 在指定页偏移写入垃圾（页级损坏）；文件注入｜截断 db 文件保留前半；文件注入｜把 db 文件清零；文件注入｜删除或截断 `-wal` 与 `-journal` 文件；文件注入｜用同名随机文件替换 db。
- 日志/Trace：`database disk image is malformed`；RDB store open 失败 errcode；`SQLITE_CORRUPT` 与 `SQLITE_NOTADB`；完整性校验失败日志；HiSysEvent 数据库损坏事件。
- 消减建议：写入前备份并在启动时做完整性校验（`PRAGMA integrity_check` 或轻量校验和）；WAL 与主库分别备份，避免同一次掉电同时破坏；损坏时按"备份恢复到重建到上报"的顺序降级；关键数据多副本；对索引与实际行数增加一致性对账；禁止把 db 文件放在会被截断或清零的临时分区。

### D-02 版本升级 / 迁移失败
- 典型原因：onUpgrade 逻辑遗漏中间版本路径；迁移 SQL 未考虑脏数据；升级中断。
- 典型影响：升级后数据丢失或应用无法启动（版本号错乱）。
- 故障注入：构造低版本脏数据 db 执行升级；升级中途 kill。
- 日志/Trace：迁移失败日志含 from/to version。
- 消减建议：全版本路径单测；迁移放事务内；失败回滚并保留原库。

### D-03 事务未回滚 / 半提交
- 典型原因：多步写操作未包事务；异常路径漏 rollback；跨 db/跨文件操作无一致性设计。
- 典型影响：数据不一致（钱扣了单没下类的业务错误）。
- 故障注入：在多步写中间注入失败。
- 日志/Trace：rollback 日志；一致性校验告警。
- 消减建议：事务包裹多步写；RAII 事务对象；跨资源操作设计对账/补偿。

### D-04 SQL 注入 / 拼接未参数化
- 典型原因：外部输入直接拼 SQL 字符串。
- 典型影响：数据泄露/篡改（安全）。
- 故障注入：输入含引号/注释符的恶意字符串。
- 日志/Trace：SQL 语法错误日志是暴露信号。
- 消减建议：一律使用参数化绑定（predicates/args）。

### D-05 游标 / 连接 / 结果集泄漏
- 典型原因：查询后未 close ResultSet；异常路径泄漏。
- 典型影响：内存膨胀、连接耗尽后所有 db 操作失败。
- 故障注入：循环查询观察内存与连接数。
- 日志/Trace：RDB 泄漏告警日志。
- 消减建议：RAII/作用域管理 ResultSet；静态检查。

### D-06 大数据量操作超时 / 卡顿
- 典型原因：主线程执行全表查询/批量写；无分页、无索引。
- 典型影响：ANR、IPC 线程被占满阻塞其他请求。
- 故障注入：灌入十万级数据后触发查询。
- 日志/Trace：慢查询日志；ANR trace。
- 消减建议：耗时 db 操作异步化；索引优化；分页与限流。

### D-07 并发写冲突 / 死锁
- 典型原因：多线程同库写无串行化；WAL 模式下读写冲突未重试（SQLITE_BUSY）。
- 典型影响：写失败丢数据；线程互相等待卡死。
- 故障注入：多线程并发写压测。
- 日志/Trace：SQLITE_BUSY/SQLITE_LOCKED errcode 日志。
- 消减建议：写操作串行队列；BUSY 重试退避；检查返回值。

### D-08 返回值与空结果未处理
- 典型原因：Query/Insert/Update 返回值未判；空结果集直接取值。
- 典型影响：空指针崩溃、错误默认值被采信。
- 故障注入：查询不存在的主键；删除依赖数据后访问。
- 日志/Trace：faultlog 空指针崩溃栈。
- 消减建议：统一检查 errcode 与行数；空结果走显式分支。
### D-09 主备双库其一损坏
- 典型原因：主库或备库单侧损坏（掉电半写、存储坏块、单侧写入中断），另一侧完好；主备同步中断导致备库滞后或写入不完整；备库长期不做校验而带病存在；切换逻辑存在但从未演练。
- 典型影响：若备库可用且切换逻辑有效，业务基本无损；但备库若从未演练过切换，切换路径本身可能失败；若主库损坏而切换逻辑缺失或未生效，则退化为 D-10 的双库不可用；单侧静默损坏（如 D-01a 第 4 类索引不一致）可能在切换后才暴露。
- 故障注入：文件注入｜仅损坏主库并保留备库完好；文件注入｜仅损坏备库并保留主库完好；两种顺序各测一次；切换过程中再次注入失败验证切换的健壮性。
- 日志/Trace：主备状态与切换事件日志（应含切换原因与耗时，多数实现缺失，应补）；单侧完整性校验失败日志；同步滞后量日志。
- 消减建议：主备两侧独立校验，不因一侧健康而跳过另一侧；把切换路径纳入例行演练，不能只写不练；切换完成后对损坏侧做重建而不是就地修复；记录切换原因与耗时用于事后复盘；备库校验结果单独上报事件，避免被主库正常状态掩盖。

### D-10 主备双库同时损坏
- 典型原因：主备遭遇同源故障（同一掉电窗口、同一存储分区、同一批写入逻辑缺陷）；备库实际是主库的同周期副本而非可独立恢复的陈旧备份；两库共用同一密钥而密钥丢失；所谓双库同盘同分区，物理上并非独立副本；写入路径上的一次错误同时破坏两侧。
- 典型影响：数据不可恢复，业务彻底失效；若为主系统服务的持久化数据则反复启动失败；用户侧表现为数据清零或应用被重置。
- 故障注入：文件注入｜同时损坏主备两库；文件注入｜在同盘写入垃圾后观测两库是否同时受影响（用于验证物理独立性）；环境与配置注入｜删除主备共用的密钥；资源压力注入｜模拟同分区坏块。
- 日志/Trace：两侧校验同时失败日志；重建或重置动作日志；数据丢失上报事件；启动失败与重启链日志。
- 消减建议：审计双库的物理独立性（是否同盘、同分区、同进程、同一批写入路径），这是该模式最常被忽略的根因；备库采用错峰写入与独立校验，避免与主库共享同一掉电窗口；密钥分离存储；明确不可恢复时的降级路径（重建默认值并明确提示用户，而不是静默清零）；关键数据增加离线或云端副本。

### D-11 数据库未持锁访问 / 锁语义失效
- 典型原因：写入方未按约定获取库级锁或文件锁即读写（旁路直写）；锁的作用域错误，进程内互斥锁保护不了跨进程访问；锁文件位于会被清理的目录，重启后锁失效而访问继续；WAL 模式下读方未处理 `SQLITE_BUSY` 即认为写入已完成；多方各自持有不同类型的锁（进程内 mutex 与文件锁混用），互不感知。
- 典型影响：数据错乱与丢更新（read-modify-write 序列丢失中间写入）；静默写坏而两侧都不报错，比直接失败更难定位；极端情况与 D-01a 叠加触发 db 损坏；故障表现为 owner 模块异常而根因在旁路写入方，责任边界难以界定。
- 故障注入：文件注入｜在持锁协议之外增加一条旁路写入路径（绕过 owner 接口直写 db）；文件注入｜删除或改写锁文件后继续访问；IPC 消息注入｜构造多进程并发写且只让其中一方持锁；时序注入｜在持锁期间注入延迟，放大竞争窗口。
- 日志/Trace：`SQLITE_BUSY` 与 `SQLITE_LOCKED` errcode 日志；锁获取与释放失败日志（多数实现缺失，应补埋点）；一致性校验失败告警；锁文件读写异常日志。
- 消减建议：确立单写者原则，跨模块写入一律经 owner 的接口，禁止直写；把锁的粒度与作用域写入设计文档（进程内锁与文件锁的覆盖范围不同，不能互相替代）；`SQLITE_BUSY` 必须重试退避，不得直接放弃；锁文件放在不被清理的目录并校验其可用性；对旁路直写增加静态扫描（参见 `11-high-risk-operations.md` 的 H-06 直接操作非本模块创建的数据库）。

> 应用层 DataShareExtensionAbility 启动与数据库操作超时场景，参见 `12-app-framework.md` 中 AF-18 ~ AF-19。
> 数据库文件损坏的底层存储视角（掉电半写、坏块、全零文件），参见 `14-hardware-driver.md` 中 HW-06a。
