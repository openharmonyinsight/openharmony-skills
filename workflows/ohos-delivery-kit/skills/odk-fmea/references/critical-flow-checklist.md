# 关键流程反思清单

> 本节自 SKILL.md 移入（渐进披露）。对每一条涉及关键流程（启动、通信、数据持久化、并发调度）的故障模式，必须逐项反思，并在表格"故障影响/故障原因"列体现结论：

1. **运行实体**：这段代码运行在哪个实体中？是系统服务（SystemAbility / foundation）、应用的中间件（NAPI 动态库 / ExtensionAbility）、还是应用主线程？运行实体决定故障影响面（系统级故障 vs 应用级故障）。
2. **阻塞风险**：会不会卡死或长耗时造成关键线程阻塞（主线程应用冻屏 AppFreeze、IPC 线程池耗尽、看门狗超时、SystemAbility 启动超时）？SA 对外同步接口是否可能长耗时（同步调用底层 IO/网络/其他 SA、持锁等待）？同步等待是否有超时保护？
3. **资源上限**：是否考虑过各类资源上限及超限后的行为：IPC 线程数量上限（线程池被打满后新调用排队或失败）、内存上限（缓存无界增长触发 OOM 或被系统查杀）、磁盘容量上限（写满后数据损坏连锁）、句柄与线程数量上限？
4. **过载与降级**：IPC 接口被对端高频反复调用（异常客户端风暴、循环重试）时，服务端是否存在限流、熔断、去重、排队上限等降级措施？还是被拖垮后所有正常客户端连锁失效？
5. **状态机与主循环**：模块内部状态机和主消息循环是否存在状态迁移出错的路径（非法事件导致状态错乱、异常分支漏迁移、并发事件乱序）？什么情况下会被逻辑卡死（等待永不满足的条件、状态停留在中间态无出口、消息循环被单条消息独占）？
6. **输入校验**：对外部输入（IPC 参数、Intent/Want、配置文件、网络数据、用户输入）有没有严格校验（空值、长度、范围、格式、权限）？
7. **文件与数据库防御**：文件与数据库操作有没有异常防御（打开失败、读写错误、磁盘满、数据损坏、升级迁移失败、并发访问冲突）？
8. **依赖返回值处理**：对底层依赖模块（HDF 驱动、内核接口、其他子系统）和 IPC 对端的返回值有没有完整处理（errcode 全枚举、空 reply、对端死亡、超时）？还是只处理了成功路径？
9. **外部数据可信性**：跨进程、跨设备、来自网络的数据是否默认可信？反序列化、长度字段、句柄传递是否可被伪造？
