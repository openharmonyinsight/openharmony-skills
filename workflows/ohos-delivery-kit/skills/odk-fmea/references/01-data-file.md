# 数据文件故障模式

### F-01 文件损坏
- 典型原因：写入过程中掉电或进程被杀，未采用临时文件加 rename 的原子替换；缺少 CRC 或长度校验；写入路径存在短写未处理；外部篡改或存储故障。
- 典型影响：重启后解析失败、配置丢失、功能不可用；严重时可导致系统服务启动失败并反复重启；若损坏未被识别，错误数据会被业务采信。
- 故障注入：在写文件中途 kill 进程或断电；按写入点切割截断文件；篡改字节破坏校验和；把文件清零。
- 日志/Trace：文件解析失败日志（`parse failed`、`invalid`）；校验失败日志；期望有 HiSysEvent 文件损坏事件。
- 消减建议：写入走 临时文件加 fsync 加 rename 的完整原子序列；读取前校验魔数、长度与校验和；损坏时按"备份恢复到重建默认值"的顺序降级并上报事件。

**常见损坏与异常类型清单**（文件类故障的判定基线，逐类核对，不要只写"文件损坏"）：

| 类型 | 触发条件 | 典型表现 | 故障注入建议 | 观测点 |
|---|---|---|---|---|
| 文件不存在 | 首次运行尚未创建；路径错配或被清理；上一步操作提前返回导致后续 open 落空 | open 返回 ENOENT；功能首次可用而后续失效 | 文件注入｜删除目标文件 | open 失败 errno 日志 |
| 0 字节 | 创建成功但写入前中断；`open(O_CREAT)` 后未写入；掉电落在创建与写入之间 | 长度校验被绕过（长度合法地等于 0）；解析得到空对象且不报错 | 文件注入｜`truncate -s 0` | 解析结果为空但无任何报错 |
| 没权限 | 沙箱与多用户路径错配；SELinux 拒绝；umask 或属主变更；多用户切换后路径失效 | open 返回 EACCES 或 EPERM；功能静默失效 | 文件注入｜`chmod 000`，或变更属主后以另一用户身份运行 | EACCES errno 日志 |
| 数据只有一半 | 部分写入（短写）未处理；掉电或进程被杀发生在写入中途；缺 fsync 导致尾部未落盘 | 文件长度合法但尾部内容缺失；解析后得到半新半旧数据 | 文件注入｜按写入点切割截断，保留前半 | 长度与内容不匹配；校验和失败 |
| 畸形内容 | 字段越界；魔数错误；长度字段被伪造；格式非法或版本不匹配；被外部篡改 | 解析失败、越界读、崩溃；或错误数据被采信为有效值 | 文件注入｜fuzz 头部与长度字段（畸形魔数、超长字段、负长度） | 解析失败日志带字段位置；faultlog 崩溃栈 |
| fd 误用 | 同一句柄被关闭两次；关闭后仍读写；跨模块传递未约定所有权；句柄被重新分配后误用 | 误关闭其他线程或模块的句柄导致数据损坏；EBADF；操作到错误对象 | PLT hook｜wrap `close` 与 `read`／`write`，按调用序号注入重复关闭或关闭后读写 | EBADF errno；fdsan 报告；数据错乱现象 |
| fd 超限 | 句柄泄漏累积；单次批量打开过多；进程或系统句柄表耗尽 | open 返回 EMFILE 或 ENFILE；此后文件与网络能力同时失败 | 资源压力注入｜调小 `ulimit -n`，或循环 open 至耗尽 | EMFILE errno；fd 统计 dump |

- 按类型对应的消减要点：文件不存在走首次创建或明确提示用户；0 字节应视为损坏而非合法空值；权限失败分级处理并上报；写入一律走临时文件加 fsync 加 rename；读取前校验魔数与校验和；句柄统一用 RAII 封装，禁止跨模块转移所有权；设置句柄上限并监控水位。

> 说明
>
> 其中"文件不存在"与"没权限"的完整场景另见 F-02；"fd 误用"与"fd 超限"的机制面另见 F-06 与 `15-process-fault.md` 的 P-02c。本表的作用是把"文件损坏"拆到可判定的粒度，避免分析时笼统写"文件损坏"。

### F-01a 写入过程掉电窗口分析（专项考虑）
- 典型原因（按写入路径逐点排查掉电窗口）：
  1. **原地覆写**：直接 open(O_TRUNC)+write 覆盖原文件，掉电后旧数据已破坏、新数据不完整，两头落空。
  2. **缺 fsync/fdatasync**：数据停留在 page cache，write 返回成功 ≠ 落盘，掉电丢失"已确认"的写入；只 fsync 文件不 fsync 目录，rename 结果本身也可能丢失。
  3. **多文件非事务写入**：配置 A、B 需一致更新，逐个写无事务，掉电在两者之间 → 版本错乱（A 新 B 旧）。
  4. **元数据与数据不一致**：文件长度已更新但内容未落盘（或反之），读到"合法长度+垃圾内容"，绕过简单长度校验。
  5. **写与读无代际标记**：无 magic/版本号/序列号，半新半旧文件无法被识别。
  6. **掉电后无自愈**：启动时不做损坏检测与恢复，带着损坏文件继续运行，故障从一次性数据丢失升级为反复崩溃/启动失败。
- 典型影响：配置/状态丢失、数据不一致被采信、系统服务启动失败循环重启、设备变砖风险（关键分区文件）。
- 故障注入：写中途断电（继电器/掉电脚本）循环压测；在每个写入点（open/write/fsync/rename 之间）分别注入掉电；写后立刻断电再上电校验内容。
- 日志/Trace：启动时文件校验失败日志（应含文件路径、期望/实际 CRC）；HiSysEvent 文件损坏事件；恢复动作（备份回滚/重建默认值）日志。
- 消减建议：①写临时文件 → fsync(文件) → rename → fsync(目录) 的完整原子序列；②重要文件保留 .bak 备份，启动时校验失败自动回滚；③多文件一致性用代际号/清单文件（最后写 commit 标记）；④启动路径必须有损坏检测+自愈分支，且自愈结果上报事件；⑤掉电窗口写入加入断电压测用例。

### F-02 文件不存在 / 路径错误 / 权限不足
- 典型原因：未判 access/open 返回值；硬编码路径与多用户/沙箱路径不匹配；SELinux 权限缺失；属主或权限位被变更；多用户切换后路径失效。
- 典型影响：功能静默失效或崩溃（空 fd 继续读写）。
- 故障注入：文件注入｜删除目标文件；文件注入｜`chmod 000` 去除权限；环境与配置注入｜切换用户身份运行；文件注入｜变更属主。
- 日志/Trace：open 失败 errno（ENOENT/EACCES）日志。
- 消减建议：检查 open/access 返回值并分级处理（可缺省 vs 致命）；路径通过系统接口获取；权限失败上报事件。
> 本条对应 F-01 类型清单中的"文件不存在"与"没权限"两类，判定口径以该清单为准。

### F-03 磁盘满 / 配额耗尽
- 典型原因：写前未检查剩余空间；写失败未处理 partial write；日志/缓存无大小上限。
- 典型影响：数据丢失、写半文件（与 F-01 叠加）、同分区其他功能连锁受损。
- 故障注入：dd 填满分区后触发写操作。
- 日志/Trace：ENOSPC errno 日志；磁盘水位 HiSysEvent。
- 消减建议：写前 statfs 检查；处理短写；缓存/日志设上限与轮转；失败时清理临时文件。

### F-04 解析失败（格式非法 / 越界 / 版本不兼容）
- 典型原因：解析外部文件时未校验长度字段/魔数；结构体直接 memcpy（对齐/大小端/版本差异）。
- 典型影响：崩溃、越界读（安全漏洞）、错误数据被采信。
- 故障注入：fuzz 输入文件（畸形头、超长字段、负长度）。
- 日志/Trace：解析失败日志带字段位置；faultlog 崩溃栈。
- 消减建议：逐字段边界校验；版本号协商与兼容分支；使用带校验的反序列化框架。

### F-05 并发读写竞争
- 典型原因：多线程/多进程读写同一文件无锁；读改写（read-modify-write）无原子性。
- 典型影响：数据错乱、丢更新、读到半新半旧内容。
- 故障注入：多线程并发读写压测；两个进程同时写。
- 日志/Trace：数据不一致的表现日志；flock 失败日志。
- 消减建议：文件锁（flock）或进程内互斥；写用原子替换；明确单写者原则。

### F-06 fd / mmap 资源泄漏与超限
- 典型原因：异常路径未 close/munmap；循环中反复 open；句柄上限配置过低或未监控水位。
- 典型影响：句柄耗尽（EMFILE/ENFILE）导致全进程文件、网络与 IPC 连锁失败。
- 故障注入：资源压力注入｜循环触发含泄漏路径的操作并观察 `/proc/<pid>/fd` 增长；资源压力注入｜调小 `ulimit -n` 后触发正常操作路径。
- 日志/Trace：open 失败 EMFILE 日志；fd 统计 dump；HiAppEvent 资源泄漏事件（fd 维度）。
- 消减建议：RAII 封装 fd；异常路径统一清理；定期 fd 审计；给批量打开路径设上限并监控水位。
> 本条对应 F-01 类型清单中的"fd 超限"。

### F-06a fd 误用（重复关闭 / 关闭后使用 / 所有权不明）
- 典型原因：同一句柄被关闭两次（异常路径与正常路径都执行 close）；关闭后仍 read/write；跨模块传递 fd 未约定所有权（裸 `int fd` 作参数）；句柄被重新分配给其他线程后误用；`fork` 后父子进程各自关闭同一句柄。
- 典型影响：误关闭其他线程或模块刚分配的同号句柄，导致数据损坏或安全漏洞；EBADF 返回被忽略后操作到错误对象；由于内核按最小可用号分配句柄，故障往往不在出错线程上表现，而是在其他线程以"不可能"的行为显现，问题定位代价极高。
- 故障注入：PLT hook｜wrap `close` 与 `read`／`write`，按调用序号注入重复关闭或关闭后读写；文件注入｜在约定之外增加旁路句柄传递路径；编译期注入｜构造异常分支与正常路径都执行 close 的代码。
- 日志/Trace：EBADF errno 日志；fdsan 报错（owner tag 不匹配、重复关闭）；数据错乱现象日志（常无直接报错，需靠一致性校验发现）。
- 消减建议：句柄所有权在接口层显式约定（接管所有权与仅借用分别用不同类型表达）；统一 RAII 封装并在释放后置为无效值；禁止裸 `int fd` 跨模块传递；对 fdsan 覆盖不全的模块补齐 owner tag；静态扫描 close 调用点做配对审计。
> 本条对应 F-01 类型清单中的"fd 误用"；fdsan 规则与代码检视清单参见 `05-libc.md` 与 `10-cutils-parcel.md`。

### F-07 路径穿越 / 符号链接攻击
- 典型原因：拼接外部传入路径未规范化；跟随符号链接未校验真实路径。
- 典型影响：越权读写沙箱外文件（安全）。
- 故障注入：传入 `../` 路径；预置指向敏感文件的符号链接。
- 日志/Trace：路径校验拦截日志。
- 消减建议：realpath 规范化后校验前缀白名单；O_NOFOLLOW。

### F-08 敏感数据明文落盘
- 典型原因：日志/缓存/临时文件输出明文密钥、token、个人信息。
- 典型影响：数据泄露（合规与安全）。
- 故障注入：静态扫描日志语句；导出应用数据目录检查。
- 日志/Trace：不涉及运行日志，属静态合规项。
- 消减建议：敏感字段脱敏；HUKS/加密存储；临时文件权限 0600。
