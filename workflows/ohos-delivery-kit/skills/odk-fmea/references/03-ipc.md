# IPC 故障模式

### I-01 对端进程死亡
- 典型原因：未注册 OnRemoteDied；对端崩溃后句柄失效仍调用。
- 典型影响：调用抛异常/永久阻塞；功能静默失效且无恢复。
- 故障注入：kill 对端进程后触发 IPC 调用。
- 日志/Trace：OnRemoteDied 回调日志；IPC 调用失败 errcode（如 DeadObject）。
- 消减建议：注册死亡通知并重连/降级；调用包裹异常处理。

### I-02 IPC 调用阻塞 / 超时 / ANR
- 典型原因：主线程同步 IPC；对端处理慢或死锁；无超时机制。
- 典型影响：主线程 ANR；SystemAbility 间互相等待导致系统级卡死。
- 故障注入：对端注入 sleep/死循环；慢速设备压测。
- 日志/Trace：主线程 ANR trace；binder 调用耗时统计。
- 消减建议：关键路径改异步 IPC；同步调用移出主线程；设置超时与看门狗。

### I-03 返回值未完整处理
- 典型原因：只处理成功路径；errcode 未全枚举；reply 未判空/未校验长度。
- 典型影响：错误数据被采信、异常崩溃、失败被误认为成功。
- 故障注入：对端返回各类 errcode/空 reply/截断数据。
- 日志/Trace：IPC 返回 errcode 日志（很多代码缺失）。
- 消减建议：errcode 全覆盖分支+默认分支；reply 先校验再读；失败路径补日志。

### I-04 序列化 / 反序列化不匹配
- 典型原因：Parcel/MessageParcel 读写顺序/类型不一致；接口版本升级未兼容。
- 典型影响：解析错乱、越界读、崩溃。
- 故障注入：构造字段缺失/类型错误的 Parcel。
- 日志/Trace：unmarshalling 失败日志；faultlog 崩溃栈。
- 消减建议：读写对称性单测；接口带版本号；读取前校验剩余长度。

### I-05 大数据传输超限
- 典型原因：通过 binder 传递大数组/位图未走共享内存；事务 buffer 超限（约 1MB）。
- 典型影响：TransactionTooLarge 类失败；大量小 IPC 导致性能劣化。
- 故障注入：传递超过 buffer 上限的数据。
- 日志/Trace：IPC 传输失败 errcode 日志。
- 消减建议：大数据走 Ashmem/共享内存；分片传输；调用前估算大小。

### I-06 调用方身份 / 权限未校验
- 典型原因：Stub 端未校验调用方 UID/PID/权限（ACL/Permission）；敏感接口无鉴权。
- 典型影响：越权调用（安全），恶意应用触发系统能力。
- 故障注入：以无权限身份调用敏感接口。
- 日志/Trace：权限拒绝日志；安全审计事件。
- 消减建议：入口统一鉴权（AccessToken/UID 白名单）；最小权限原则。

### I-07 Stub 端异常未捕获
- 典型原因：服务端实现中异常未 catch，直接穿透 IPC 层。
- 典型影响：服务端进程崩溃，所有客户端连锁失效（对系统服务是系统级故障）。
- 故障注入：传入触发服务端异常分支的参数。
- 日志/Trace：服务端 crash faultlog。
- 消减建议：Stub 入口统一 try-catch，异常转 errcode 返回。

### I-08 回调注册泄漏 / 重复注册
- 典型原因：注册回调后未注销；重复注册不去重；回调持有对象引用导致泄漏。
- 典型影响：回调风暴、内存泄漏、对象释放后被回调（UAF 崩溃）。
- 故障注入：反复注册/注销；释放对象后触发事件。
- 日志/Trace：注册计数日志；faultlog 崩溃栈。
- 消减建议：注册/注销配对；以 token 去重；回调用弱引用。

### I-09 嵌套同步 IPC 死锁
- 典型原因：A 同步调 B 的同时 B 同步回调 A；持锁期间发起同步 IPC。
- 典型影响：双方线程永久卡死，系统服务级冻结。
- 故障注入：构造双向同步调用场景。
- 日志/Trace：看门狗超时事件；IPC 线程堆栈 dump 显示互等。
- 消减建议：禁止持锁同步 IPC；回调改异步；调用关系单向化。

### I-10 高频反复调用无降级措施
- 典型原因：服务端未做限流/去重/排队上限；异常客户端死循环重试或回调风暴把 IPC 线程池打满。
- 典型影响：IPC 线程数量到达上限后新调用排队甚至失败，正常客户端连锁超时（表现为大面积"随机"卡顿）。
- 故障注入：用测试客户端以高频率循环调用目标接口；并发多客户端压测。
- 日志/Trace：IPC 调用耗时与队列深度统计；服务端限流拒绝日志（多数缺失，应补埋点）。
- 消减建议：入口限流（令牌桶/并发上限）；幂等去重；失败退避约定告知客户端；过载时快速失败并上报 HiSysEvent。

## 应用接口层故障（API / Service Interface Business Layer）

> 与上方 I-01 ~ I-10（IPC 底层通用故障）互补：本类关注业务接口的契约履行（返回值语义、响应性、服务可用性），而非 IPC 传输机制本身。

### I-11 接口返回失败未处理（Interface Return Failure Unhandled）
- 典型原因：业务代码只处理成功路径（SUCCESS），忽略 errcode 失败分支；错误码未映射到业务降级策略；跨层传递时错误码被吞没或篡改。
- 典型影响：模块业务处理异常/失败被静默忽略，后续操作基于错误状态继续执行，导致数据错乱或级联故障。
- 故障注入：Mock 服务端返回各类 errcode（PERMISSION_DENIED、TIMEOUT、DEAD_OBJECT、UNKNOWN_ERROR）；构造网络断开/服务未启动场景。
- 日志/Trace：接口调用返回 errcode 日志（多数代码缺失失败分支日志）；业务异常链断裂（上层无日志）。
- 消减建议：errcode 全分支覆盖 + 默认降级分支；失败路径必须埋点（HiLog/HiSysEvent）；跨层传递错误码保持语义不丢失。

### I-12 接口无响应 / 调用 hang（Interface Unresponsive）
- 典型原因：同步调用无超时保护；对端服务死锁或主线程阻塞；网络分区导致 RPC 长期挂起；未区分"失败"与"未响应"状态。
- 典型影响：调用方模块业务处理失败/中断；线程池被长期占用；级联超时导致系统服务雪崩。
- 故障注入：对端服务注入死循环/睡眠；断开网络后触发同步 RPC；构造对端进程冻结场景。
- 日志/Trace：调用方线程堆栈停在 IPC/RPC 等待；看门狗超时事件；调用耗时统计（超过阈值无返回）。
- 消减建议：同步调用强制设置超时（如 5s）；超时后转异步回调或降级；调用方线程池隔离（防止占满）；无响应状态独立上报（与"失败"区分）。

### I-13 剪切板 Service 异常（Clipboard Service Exception）
- 典型原因：剪切板服务（Pasteboard Service）进程崩溃或异常退出；跨设备复制粘贴依赖的分布式服务未就绪；剪贴数据过大或格式不兼容导致服务处理异常。
- 典型影响：跨设备复制粘贴失败；用户数据无法跨设备流转；剪贴板功能整体不可用。
- 故障注入：kill 剪切板服务进程；构造超大剪贴数据（> 阈值）；跨设备场景断开网络后触发复制。
- 日志/Trace：剪切板服务死亡事件（OnRemoteDied）；跨设备粘贴失败 errcode；服务重启日志。
- 消减建议：剪切板服务崩溃后自恢复（由 appspawn/SAMGR 保活）；客户端调用包裹异常处理，失败时降级为本地剪贴板；大数据分片传输；跨设备场景超时后提示用户。

## 消息通信层故障（Message / IPC / RPC Business Layer）

> 与上方 I-01 ~ I-10（IPC 传输层故障）互补：本类关注消息内容的业务语义正确性与流量控制，而非 binder/parcel 传输机制。

### I-14 消息无响应（Message No Response）
- 典型原因：消息发送后未设置超时/重试；对端消息处理线程死锁或阻塞；消息队列积压导致消息长期未消费；RPC 对端未启动或网络不可达。
- 典型影响：业务中断，模块业务处理失败；发送方阻塞等待或永久挂起；事务状态不一致（已发送未确认）。
- 故障注入：对端消息处理注入 sleep/死锁；构造消息队列满场景；断开网络后发送 RPC。
- 日志/Trace：消息发送超时事件；消息队列深度统计；对端线程堆栈 dump；事务状态不一致日志。
- 消减建议：消息发送设超时与重试（指数退避）；消息队列设深度上限与告警；对端无响应时转降级或事务回滚；异步消息模式替代同步阻塞。

### I-15 消息内容错误（Message Content Error）
- 典型原因：消息序列化/反序列化不匹配（字段顺序、类型、版本差异）；消息在传输中被篡改或截断；业务状态机与消息语义不一致（如重复消息、乱序消息）。
- 典型影响：业务中断，模块业务处理失败；错误数据被采信导致状态错乱；级联故障（错误消息触发对端异常处理）。
- 故障注入：构造字段错位/类型错误的 Parcel/Message；篡改消息 payload；发送重复/乱序消息。
- 日志/Trace：消息解析失败日志（unmarshalling error）；业务状态校验失败日志；faultlog 崩溃栈（若解析越界）。
- 消减建议：消息格式带版本号与 CRC 校验；反序列化前校验长度与魔数；业务层幂等去重；状态机校验消息合法性（非法消息拒绝并告警）。

### I-16 消息过载 / 流控失效（Message Overload / Flow Control Failure）
- 典型原因：消息生产速率远高于消费速率且无流控；突发流量（如广播风暴、批量同步）超过消息队列容量；流控机制配置错误或未生效。
- 典型影响：消息队列内存膨胀导致 OOM；消息丢弃导致业务丢失；消费端处理延迟级联放大；系统卡顿或崩溃。
- 故障注入：高频循环发送消息压测；构造消息风暴（如批量同步 10万条消息）；填满消息队列观察丢弃行为。
- 日志/Trace：消息队列深度告警；流控触发日志（丢弃/限速）；内存增长曲线；HiAppEvent 资源泄漏事件。
- 消减建议：消息流控机制（令牌桶/漏桶/队列深度上限）；生产者限速与背压（backpressure）；队列满时降级（丢弃非关键消息/通知生产者）；消息批量合并与压缩；流控效果监控与告警。
> 应用层 Binder 资源耗尽与对端卡死业务场景，参见 `12-app-framework.md` 中 AF-20 ~ AF-22。
> 业务层接口契约失败（返回失败未处理、无响应、剪切板服务异常）与消息语义层故障（无响应、内容错误、过载），参见 `03-ipc.md` 中 I-11 ~ I-16。
