# FFRT 故障模式 触发索引

> 两级加载第一级：只读本表做扫描判定；条目触发条件命中后，到 [../04-ffrt.md](../04-ffrt.md) 读取该 `### ID` 条目详情（大文件可用 Read offset/limit 按锚点局部读）。

| ID | 故障模式 | 触发条件（可判定的代码/设计特征） |
|---|---|---|
| R-01 | 任务泄漏 / 句柄未释放 | ffrt::submit 后 handle 未 wait/释放（无 RAII）；循环提交无上限与有界队列 |
| R-02 | 依赖关系错误 | wait 的依赖未 submit、顺序颠倒或循环依赖；提交前无依赖有效性断言 |
| R-03 | 任务内异常未捕获 | 任务 lambda 内无统一 try-catch 入口（异常穿透 FFRT 框架直接终止进程） |
| R-04 | 优先级反转 / 关键任务饿死 | 关键任务（UI/IPC 响应）与高负载任务共用队列且无 QoS 分级；低优先级长任务可长占线程 |
| R-05 | 队列阻塞 / 线程池耗尽 | 任务内执行同步 IPC/IO/sleep 等阻塞调用；阻塞操作未走专用线程 |
| R-06 | 生命周期问题（任务访问已释放对象） | lambda 捕获 this/裸指针且对象析构时不 wait/cancel 未完成任务 |
| R-07 | cancel 语义误用 | 假设 cancel 立即生效不查返回值；任务已运行被 cancel 后无状态清理与协作式取消点 |
