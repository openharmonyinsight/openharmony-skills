# 数据库故障模式 触发索引

> 两级加载第一级：只读本表做扫描判定；条目触发条件命中后，到 [../02-database.md](../02-database.md) 读取该 `### ID` 条目详情（大文件可用 Read offset/limit 按锚点局部读）。

| ID | 故障模式 | 触发条件（可判定的代码/设计特征） |
|---|---|---|
| D-01 | 数据库打开失败 | RDB/sqlite open 返回值未按 errcode 分级处理；db 路径硬编码（多用户/沙箱/SELinux 场景可能错配）；加密库依赖 HUKS 密钥而无密钥缺失分支 |
| D-01a | 数据库文件损坏 | 写库未启用 WAL/事务（存在掉电半写风险）；启动时无 `PRAGMA integrity_check` 或校验和；无备份恢复到重建默认值的降级路径；索引与行数据无一致性对账 |
| D-02 | 版本升级 / 迁移失败 | onUpgrade 迁移逻辑缺中间版本路径（v1→v3 无 v2）；迁移 SQL 未处理脏数据；迁移未包事务且无失败回滚 |
| D-03 | 事务未回滚 / 半提交 | 多步写操作未包事务；异常路径漏 rollback（无 RAII 事务对象）；跨 db/跨文件操作无对账补偿设计 |
| D-04 | SQL 注入 / 拼接未参数化 | 外部输入直接拼接 SQL 字符串（未用参数化绑定 predicates/args） |
| D-05 | 游标 / 连接 / 结果集泄漏 | 查询后未 close ResultSet（无 RAII/作用域管理）；异常路径泄漏连接；循环查询场景无泄漏监控 |
| D-06 | 大数据量操作超时 / 卡顿 | 主线程执行全表查询或批量写；无分页与索引优化；耗时 db 操作未异步化（taskpool/工作线程） |
| D-07 | 并发写冲突 / 死锁 | 多线程同库写无串行队列；WAL 模式下 `SQLITE_BUSY`/`SQLITE_LOCKED` 未重试退避 |
| D-08 | 返回值与空结果未处理 | Query/Insert/Update 返回值与行数未判定；空结果集直接取值（无显式空分支） |
| D-09 | 主备双库其一损坏 | 存在主备双库设计；备库无独立完整性校验（带病存在）；切换逻辑从未演练；单侧损坏后无重建路径 |
| D-10 | 主备双库同时损坏 | 主备双库同盘/同分区/同进程或共享写入路径与密钥（物理非独立）；备库与主库同周期写入（共享掉电窗口）；无不可恢复时的重建默认值降级 |
| D-11 | 数据库未持锁访问 / 锁语义失效 | 绕过 owner 接口旁路直写 db；进程内 mutex 试图保护跨进程访问；锁文件位于会被清理的目录；进程内锁与文件锁混用互不感知 |
