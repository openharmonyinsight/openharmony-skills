# 数据文件故障模式 触发索引

> 两级加载第一级：只读本表做扫描判定；条目触发条件命中后，到 [../01-data-file.md](../01-data-file.md) 读取该 `### ID` 条目详情（大文件可用 Read offset/limit 按锚点局部读）。

| ID | 故障模式 | 触发条件（可判定的代码/设计特征） |
|---|---|---|
| F-01 | 文件损坏 | 写文件未走"临时文件+fsync+rename"原子序列（直接 open(O_TRUNC) 原地覆写或缺 fsync）；读取前无魔数/长度/校验和校验；写入路径短写未处理 |
| F-01a | 写入过程掉电窗口分析（专项考虑） | **独立判定，不以 F-01 命中为前提**：多个文件/库需一致更新（配置对、清单+数据、双库）且无跨文件事务或代际/commit 标记；或写入无法走完整原子序列（追加写日志、数据库原地写）；或启动路径无损坏检测与备份回滚/重建默认值自愈分支——即使单文件写入已安全（临时文件+fsync+rename 齐备）仍需本条评估 |
| F-02 | 文件不存在 / 路径错误 / 权限不足 | open/access 返回值未判定即继续使用 fd；硬编码路径在多用户/沙箱/SELinux 场景可能错配；属主或权限位可能被变更（chmod/umask） |
| F-03 | 磁盘满 / 配额耗尽 | 写前未 statfs 检查剩余空间；写失败未处理 partial write；日志/缓存/下载目录无大小上限与轮转策略 |
| F-04 | 解析失败（格式非法 / 越界 / 版本不兼容） | 解析外部或落盘文件时未校验长度字段/魔数/字段边界；对文件内容按结构体直接 memcpy（依赖对齐、大小端、版本一致） |
| F-05 | 并发读写竞争 | 多线程/多进程读写同一文件无 flock 或进程内互斥；read-modify-write 非原子；无单写者约定 |
| F-06 | fd / mmap 资源泄漏与超限 | 异常/错误路径未 close/munmap（fd 未 RAII 封装）；循环中反复 open 不释放；句柄数无上限配置与水位监控 |
| F-06a | fd 误用（重复关闭 / 关闭后使用 / 所有权不明） | 裸 `int fd` 跨模块/线程传递且未约定所有权；异常分支与正常路径可能都执行 close；close 后继续 read/write；fork 后父子进程共用句柄各自关闭 |
| F-07 | 路径穿越 / 符号链接攻击 | 拼接外部传入路径后未 realpath 规范化并做前缀白名单校验；open 未使用 O_NOFOLLOW 且目标目录可被植入符号链接 |
| F-08 | 敏感数据明文落盘 | 日志/缓存/临时文件输出密钥、token、个人信息等明文；临时文件权限未设 0600、未走 HUKS/加密存储 |
