# 质量要求

> 本节自 SKILL.md 移入（渐进披露）。输出前的自查清单，与 [terminology-style.md](terminology-style.md) 配套使用。

- 故障模式必须有证据支撑：代码位置、文档段落或问题单号；推测性条目在故障原因中标注"推测"。
- 不堆砌库中全部模式：每条列出的故障模式都要说明它在当前对象中为什么成立。
- 同一故障原因导致多个故障模式时，在表中分别列出并互相引用编号。
- 颗粒度分层不重复：同一根因只进一张表；跨层关联用编号引用表达，不在两张表中各写一遍。
- **仓级知识库优先且不可伪造**：仓存在 `docs/dfx/fmea.yaml` 时以其为权威来源，照录原文并给出 `<repo>@<commit>:...#<标识>` 出处；推导条目必须显式标注"本次推导"，绝不写成库命中。
- **仓不可达必须记录**：状态记为 `UNREACHABLE` 并在输出中说明待补，不得跳过该仓或以推导代替。
- **已排除项要说明**：被"非目标""设计约束"排除的故障，若接近某条候选，在附注中说明为何不列，避免读者误以为遗漏。
- **故障注入建议要可执行**：每条建议必须点名手段（文件注入 / IPC 消息注入 / PLT hook 注入 / 或补充手段）、注入点（精确到函数、文件、消息字段或调用序号）与注入内容（错误码、次数、持续时间），并满足可复现、可卸载、不改变注入点之外行为语义三条约束。只写"构造异常场景"视为未填写。
- **注入建议优先自动化**：能在单元测试或 CI 中自动重跑的方案优先于手工方案；仅能手工执行的，在建议中显式标注。
- **用语自查**：输出前按 [terminology-style.md](terminology-style.md) 的三条铁律与对照表通检一遍，重点确认无"失效模式""严重度""fd 泄漏"等非规范用词，且全文无破折号插入语。
- 输出语言默认中文。
