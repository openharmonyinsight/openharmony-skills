# 高危操作故障模式

本类覆盖**天然具有高破坏性的操作**：一旦发生或被误触发，直接造成进程消亡、数据破坏或跨模块状态错乱。分析代码时应把本类操作作为"搜索清单"先全文检索（exit/abort/quick_exit、kill、remove/unlink/rmdir、跨路径数据库打开、跨模块 free），再逐处评估其触发条件、目标合法性与可观测性。此类问题多数应归入 FMEA 的架构与设计问题表（D 级）——是否允许做、由谁做、如何做管控，是设计决策而非局部编码问题。

## 1. 进程自己退出

### H-01 业务路径误触进程退出
- 典型原因：exit/abort/quick_exit/_Exit 出现在库函数、工具函数或错误处理深层路径中，被正常业务间接触发；第三方库/公共组件内部暗藏 exit；APPSPAWN_CHECK 类宏在"不可恢复"分支直接终止进程而无现场保留。
- 典型影响：进程无预警死亡；对系统服务是系统级故障（应用全部不可用/触发 critical 重启链）；退出点无日志时定位极难。
- 故障注入：构造触发深层错误分支的输入；静态扫描全仓 exit/abort 调用点并逐一构造触发。
- 日志/Trace：faultlog 退出栈（abort 有栈，exit 无栈最危险）；退出前的最后一条业务日志；init/SAMGR 的进程死亡事件。
- 消减建议：进程退出只允许出现在入口层统一路径；库/工具函数一律返回错误码；必须退出时先打日志+上报事件+保留 dump；对子进程参考 appspawn 的 exit hook 拦截设计。

### H-02 自杀式降级设计失控
- 典型原因：以"连续失败 N 次主动退出/重启"作为自恢复手段，但计数维度错误（全局计数而非按失败来源）、阈值过严、退出前未评估影响面（如 critical 服务退出触发整机重启）。
- 典型影响：降级机制被异常输入"引爆"为 DoS；故障从局部功能失效放大为整机重启。
- 故障注入：构造恰好满足计数条件的连续失败序列，观察是否退出及后续连锁。
- 日志/Trace：计数递增日志（多数缺失）；自杀决策点事件上报；init critical 重启日志。
- 消减建议：按失败来源（uid/业务标识）维度限流替代全局自杀；自杀前上报事件并保留现场；评估 critical/看门狗参数联动的最坏后果。

## 2. 杀进程

### H-03 kill 目标校验不足 / pid 复用误杀
- 典型原因：kill(pid, SIGKILL) 的 pid 来自历史记录/IPC 消息/配置文件，未校验目标仍是"自己孵化的那个进程"（pid 退出后被系统复用）；kill 前未验证进程名/uid/启动时间；对进程组 kill 波及无辜。
- 典型影响：误杀无关进程（对系统服务可致关键服务死亡、用户数据丢失）；被恶意构造的 pid 诱导杀指定目标（安全）。
- 故障注入：记录 pid → kill 原进程 → 等 pid 复用（大量 fork）→ 触发 kill 路径。
- 日志/Trace：kill 动作日志（pid+目标进程名+调用原因，多数缺失）；被误杀进程的死亡事件。
- 消减建议：kill 前用 pidfd 或 /proc/pid/cmdline+启动时间校验目标身份；优先 pidfd_send_signal 杜绝复用问题；所有 kill 动作强制日志（who/why/when）。

### H-04 异常清理路径的连锁 kill
- 典型原因：超时/失败清理逻辑 kill 子进程后未等待回收（僵尸）；kill 信号被目标捕获忽略后无兜底 SIGKILL；清理动作与状态机迁移不配对（已 kill 但状态仍为"存活"）。
- 典型影响：僵尸进程累积；目标进程残留继续持有资源；状态机错乱导致重复 kill/误判。
- 故障注入：目标进程阻塞 SIGTERM 后触发清理路径；kill 后立即查询状态。
- 日志/Trace：kill 结果与 waitpid 结果日志；僵尸进程计数（/proc 扫描）。
- 消减建议：kill 后必须 wait/pidfd 等待确认回收；SIGTERM → 宽限 → SIGKILL 两段式；kill 与状态迁移同事务。

## 3. 非配对操作（跨模块/跨所有权操作）

### H-05 删除非本模块创建的数据
- 典型原因：清理逻辑按路径模式删除文件/目录（如清空整个共享目录、按通配符删除），目标包含其他模块/应用创建的数据；卸载/重置路径"宁可错杀"；路径拼接可被引导至他模块目录。
- 典型影响：他模块数据丢失（配置、数据库、用户文件），故障跨模块扩散且责任难以界定；删除系统文件可致设备异常。
- 故障注入：在目标目录预置他模块标记文件，触发清理路径后检查是否被误删。
- 日志/Trace：删除动作日志（路径+调用者，多数缺失）；他模块的数据丢失报错。
- 消减建议：只删除本模块创建且带可验证标识（magic/owner 文件）的数据；删除清单白名单化；高危删除前校验目录 owner；删除动作强制日志。

### H-06 直接操作非本模块创建的数据库
- 典型原因：绕过数据 owner 服务，直接打开他模块的数据库文件读写（"图省事"共享数据）；owner 模块升级 schema 后直写方数据格式腐化；两边并发写无协调（owner 用 WAL/锁，直写方绕过）。
- 典型影响：数据损坏、schema 不一致、owner 服务读到意外数据崩溃；故障表现为 owner 模块问题，根因在他处，定位困难。
- 故障注入：直写后触发 owner 服务读取/升级路径；并发压测直写方与 owner。
- 日志/Trace：db 损坏错误（malformed）；schema 版本不匹配日志；SQLITE_BUSY/CORRUPT。
- 消减建议：跨模块数据一律经 owner 的 IPC 接口访问；数据库文件权限仅 owner 可读写；确有共享需求用系统提供的数据共享机制（DataShare 等）。

### H-07 内存申请与释放不在同一模块
- 典型原因：A 模块 malloc/new 的指针传给 B 模块（跨 so）free/delete——不同 so 可能链接不同分配器/CRT（堆不一致），或接口契约未明确所有权转移；异步回调中释放方与申请方生命周期脱钩。
- 典型影响：堆破坏、double-free、偶发崩溃（跨 so 释放时释放到错误的堆），现网高发且栈信息误导。
- 故障注入：ASan 下跑跨模块传递堆对象的路径；审查跨 so 接口的所有权约定。
- 日志/Trace：ASan alloc-dealloc-mismatch/heap-use-after-free 报告；jemalloc 堆破坏 abort。
- 消减建议：跨模块接口显式定义所有权（谁申请谁释放，或提供配套 destroy 函数）；跨 so 传递优先用 fd/句柄/共享内存而非裸堆指针；接口文档标注 ownership。

### H-08 其他非配对资源操作
- 典型原因：mount/umount、加锁/解锁、注册/注销、打开/关闭跨模块或跨线程不配对（A 线程加锁 B 线程解锁、模块 A 注册回调模块 B 未注销即卸载）；引用计数跨模块增减。
- 典型影响：死锁、UAF、资源泄漏、挂载点残留导致命名空间污染。
- 故障注入：审计配对操作 grep 清单（lock/unlock、register/unregister、ref/unref）逐一比对调用点。
- 日志/Trace：TSAN/锁序报告；泄漏检测事件；UAF crash 栈。
- 消减建议：配对操作约束在同一模块同一线程；用 RAII/作用域锁强制配对；模块卸载流程强制注销检查清单。
