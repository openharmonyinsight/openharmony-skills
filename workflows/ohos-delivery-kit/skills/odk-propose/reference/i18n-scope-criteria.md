# 国际化（i18n）需求判断标准

## 核心原则

**涉及国际化的条件**：只要需求涉及**面向用户**的数据**表达、展示、解析或交互**，就应使用全球化接口（机器协议间传递/比较、内部计算且不展示给用户的数据除外——见快速判断流程第 0 步排除条件）。

**简化判断**：
- 值是否给用户看？ → 看 → 需要国际化
- 不同地区用户看到的是同一个值吗？ → 不是 → 需要
- 是人读而非机器读吗？ → 是 → 需要

**关键约束**：**组件不能假设输入数据已经满足国际化要求**。即使该需求作为数据可视化方仅提供可视化能力，也需要使用国际化接口。因为组件不能假设输入已是最终格式，即使数据提供方声称内容已处理，组件在展示层仍需具备自适应国际化的能力。原因：
- 数据提供方可能未考虑所有目标地区的格式需求
- 同一数据在不同地区需要不同的表达方式
- 组件的职责是在**展示环节**确保用户看到符合其他地区习惯的内容
- 因此，组件应调用全球化接口进行**最终展示格式**的适配，而非信任输入数据已是"已国际化"状态

## 快速判断流程

```
0. 先应用排除条件：仅当数据只面向用户展示/解析/交互时才进入后续判断。
   命中任一排除条件 → 可设置为否，不再进入1 ~ 7 步：
   - 纯技术性ID、内部编码（不展示给用户）
   - 仅用于内部计算的数值（过程和结果都不展示）
   - 网络协议时间戳（UTC标准格式，不展示给用户）
   - 数据库内部存储格式（不涉及展示层）
   - 程序读取用的配置文件数值（不用于展示）
1. 涉及文本内容的跨语言展示？        → 是 → 国际化
2. 涉及日期/时间/时间戳展示或解析？   → 是 → 国际化（含隐含时间场景）
3. 涉及数字格式化或展示？            → 是 → 国际化（含进度条、统计等隐含场景）
4. 涉及度量衡单位？                  → 是 → 国际化
5. 涉及时区/夏令时？                 → 是 → 国际化
6. 涉及排序规则或文本比较？          → 是 → 国际化
7. 涉及系统语言/区域偏好？           → 是 → 国际化
```

**复核**：快速判断为"否"时，若存在以下情况仍需审查：
- 有"显示"、"展示"、"可视化"等用户可见场景
- 实现涉及 `Date`、`Number`、`String.format`等涉及数字格式场景
- UI 模板有 `${}` 占位符

## 场景分类

### 1. 语言与区域

| 场景 | 示例关键词 |
|------|------------|
| 多语言文本处理 | "多语言"、"中英文切换" |
| 地区格式适配 | "按地区显示"、"本地化格式" |
| 系统语言/区域配置 | "获取系统语言"、"监听语言变化" |
| 用户语言偏好 | "用户首选语言"、"切换语言" |

### 2. 日期与时间

**原则**：涉及时间的展示、解析、计算、可视化，都应考虑国际化。

**显式场景**：日期格式化、星期计算、时分秒、AM/PM、时区转换、夏令时、时间戳、相对时间（"X天前"）

**隐含场景**：
| 场景 | 示例关键词 |
|------|------------|
| 消息时间戳 | "消息时间"、"发送时间"、"刚刚" |
| 文件时间 | "创建于"、"修改时间" |
| 倒计时 | "倒计时"、"还剩X天" |
| 有效期 | "有效期"、"到期" |
| 时区敏感 | "当地时间"、"出发时间" |
| 出生日期 | "出生日期"、"年龄" |

**实现线索**：使用 `Date`/`Calendar`/`LocalDate`等 类型 → 日期格式、夏令时、历法

### 3. 日历系统

涉及非公历日历或历法转换：农历、伊斯兰历、希伯来历、日本年号、历法转换、周首日设置

### 4. 数字格式化

**原则**：涉及数字的展示、输入、解析、可视化，都应考虑国际化。

**显式场景**：小数/千分位、百分比、货币、数字分组、数字精度、科学计数法、记账格式

**隐含场景**（不直接提"数字"，但实现涉及）：
| 场景 | 示例关键词 |
|------|------------|
| 进度指示 | "进度"、"加载"、"已完成X%" |
| 统计图表 | "统计"、"图表"、"柱状"、"饼图" |
| 评分系统 | "评分"、"星级"、"rating" |
| 数量统计 | "数量"、"共X条"、"库存" |
| 时间数值 | "时长"、"倒计时"、"用时X分钟" |
| 度量展示 | "距离X公里"、"速度X" |
| 金额结算 | "价格"、"金额"、"结算" |

**实现线索**：使用 `Number`/`Double`/`BigDecimal`等 展示 → 数字格式、小数点、分组

### 5. 度量衡

涉及物理量展示：长度/距离、重量、温度、速度、面积、体积、单位制切换

**隐含场景**：导航距离、BMI体脂、车速显示、天气预报、文件大小、包裹重量等

### 6. 排序与比较

涉及不同语言的排序：字符串排序、拼音排序、笔画排序、大小写敏感、重音敏感

### 7. 复数规则

涉及单复数形式变化：复数形式、词形变化、数量词搭配

### 8. 显示名称

本地化显示：语言名称、国家/地区名称、货币名称、日历类型名称、时区名称

### 9. 文本处理

Unicode归一化、组合字符、单词/句子/行边界、字符类型判断

### 10. 其他

节假日计算、实体识别（日期/电话）、音译/转写、时区数据

## 通常涉及国际化的情况

即使需求未明确提及，以下情况应引入国际化：

**时间**：使用 `Date`/`Time`/`DateTime` 等类型的展示逻辑、显示"刚刚"/"X分钟前"等、倒计时/限时/有效期

**数字**（最易被忽视）：进度条、统计图表数值、评分/排名、显示"共X条"/"已用X"、配置值展示（超时/重试次数）、时长显示

**其他**：调用`I18n*`/`Intl*` API、涉及节假日/工作日计算、中文拼音/笔画排序

## 实现反推线索

即便需求没提国际化，以下实现细节表明可能需要：


| 实现场景 | 国际化考量点 |
|----------|-------------|
| 使用 `Date`/`Calendar`/`LocalDate` | 日期格式、夏令时、历法 |
| 使用 `Number`/`Double`/`BigDecimal` 展示 | 数字格式、小数点、分组 |
| `String.format` / 模板字符串 / 占位符 | 文本顺序、数值/日期占位符 |
| UI显示相对时间 | 相对时间格式化 |
| 涉及图表数值轴 | 数字格式、分组 |
| 涉及"星期几"计算 | 一周首日因地区而异 |
| 涉及温度、数值、物理单位等展示 | 度量衡和数字格式需在展示层适配 |
| **可视化组件接收外部数据** | **展示层必须调用全球化接口适配，不能假设输入已格式化** |
