# Rule: 错误码、日志和诊断

## Rule ID

OH-ARCH-ERROR-LOG

## Applies To

- Feature Design
- Feature Spec
- Task Spec
- AI implementation
- GC 代码质量审查
- GC 最终验证审查

适用于新增错误路径、权限失败、参数校验、IPC 异常、日志、错误码、诊断工具和问题定位能力。

## Must

- 必须复用或扩展所在模块已有错误码体系。
- 必须为开发者可见或跨模块可见失败定义稳定错误码和错误描述。
- 必须说明错误触发条件、返回路径和调用方处理建议。
- 必须使用模块已有 HiLog domain/tag 或符合模块规范的新 domain/tag。
- 必须记录关键路径、异常路径和恢复路径的可定位日志。
- 必须避免日志泄露敏感信息、密钥、令牌、个人敏感数据或完整隐私内容。
- 涉及系统服务、IPC 或复杂状态时，必须说明 hidumper/hilog/debugger 等诊断方式。

## Must Not

- 禁止随意新增魔法数字错误码。
- 禁止返回无法定位原因的通用失败。
- 禁止吞掉异常或只记录无上下文日志。
- 禁止在日志中输出敏感信息。
- 禁止新增错误路径后不补充测试或人工验证步骤。

## Evidence

- 错误码表、错误描述和触发条件。
- 日志 domain/tag、日志级别和关键字段说明。
- 参数校验、权限失败、依赖失败、IPC 失败测试。
- hilog/hidumper/debugger 输出或人工验证记录。
- 安全检查结论。

## Check

- 检查错误码是否复用已有范围或有扩展依据。
- 检查每个异常路径是否有明确返回和日志。
- 检查日志是否可定位且不泄露敏感信息。
- 检查诊断证据是否能支持问题复现和归因。
