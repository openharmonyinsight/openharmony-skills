**Issue：使用 `.gitcode/ISSUE_TEMPLATE/task.yaml`**

建议标题：`[性能] 修复 <场景> 中 <操作> 耗时过高的问题`

准备以下内容：

- **问题与影响**：哪个操作变慢、触发条件、影响范围。
- **复现方法**：版本或提交号、运行环境、数据规模、执行步骤。
- **性能基线**：测量命令、重复次数、耗时或吞吐量、内存占用；没有数据则标注“待测”。
- **修复目标**：预期改善指标、需要保持的功能行为。
- **实施与验收**：拟排查的位置、修复思路、功能回归和性能对比方法。

**PR：使用 `.github/PULL_REQUEST_TEMPLATE.zh-CN.md`**

建议标题：`perf: 优化 <模块> 的 <操作> 性能`

说明应包括：

- **关联 Issue**：创建后填入实际链接，不编造编号。
- **原因与改动**：性能瓶颈是什么，修改如何减少开销。
- **验证结果**：记录实际执行的测试、环境和结果；尚未执行的项目明确标注。
- **性能对比**：在相同环境与输入下比较修复前后数据，附测量方法；没有实测结果时不声称提升比例。
- **风险与回退**：兼容性、资源消耗变化、边界情况及回退方式。

> CI：暂无结果，尚不能确认通过。

> 性能对比：待执行或补充实测数据。
> GitCode 工具未连接，Issue/PR 尚未通过工具创建，关联链接待补充。
