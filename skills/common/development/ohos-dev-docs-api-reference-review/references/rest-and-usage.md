# 使用契约、REST与体验规则

## 接口和参数契约（11.x–12.x、RULE-04）

通用的功能/参数说明、范围与单位、默认值、版本/设备/权限约束、前置条件、废弃替代及关联信息检查，引用既有技能的 completeness/capability/clarity 和 API 模板规则，不重复维护本地清单。

RULE-04 仅保留尚需语义证据的补充判据：

- RULE-04-03：配置何时生效、与何种状态冲突、何时不生效；不能只靠出现“约束”章节判满足。
- RULE-04-07：配合接口顺序、互斥关系及关联参数制约，沿实际调用路径核对。
- RULE-04-02 的增量：区分未传入与显式传值的效果；默认值是否有说明由来源技能检查，本地只核对给定语义证据，不重复计缺失项。

自包含描述范式（不是强制官方固定句式）：

- 可选参数：“未传入时采用…；当…时需显式传入…；越界时…”。未给实现证据不能擅自填省略内容。
- 废弃：“从API N起废弃；在满足…时使用X替代；差异为…”。N/X不可得标未验证，不编造替代。
- Promise/callback：“成功得到…后再…；失败通过…报告”。方式以声明为准，不能把void回调写成同步返回。

这些模板已包含必要资源正确性、完备性、易理解性检查，不要求另一个未附带的“资源模型”文件。语言风格可选配套写作技能；没有安装时不声称完成该专项全检。

## REST 分支（只在REST任务读取）

以给出的接口规格为源核对URI占位符、HTTP方法、鉴权、版本、请求参数、响应字段、状态码和错误结构。HTTP状态码与响应体业务码分开，不从“请求成功”推断所有业务分支成功。样例请求/响应应同场景一致；没有实际服务响应则行为正确性未验证。

## 体验提升（29.x，仅按需）

29.1.1信息量、.2概念概述、.3功能分组、.4表格密度、.5层次、.6概述、.7继承依赖、.8状态图、.9原理深度、.10调用流程、.11关联索引。先证明对应解释对使用任务必要，才报缺口；这些条目没有固定高/中颜色，统一依实际影响定级。

专项报告例：`api.md:18` 已说明“timeout未传入时采用1000ms”，给定匹配版本规格却明确“未传入时采用500ms，显式传入0才表示不超时”→本地RULE-04-02语义增量，可确认缺省效果与证据冲突；建议按所给规格修正，并区分未传与显式0。这里不报告“默认说明缺失”；若只是没写单位/默认值，应交来源completeness规则，不计本地专项覆盖。
