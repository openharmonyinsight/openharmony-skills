# 使用契约、REST与体验规则

## 接口和参数契约（11.x–12.x、RULE-04）

接口定义3要素：含义/功能、使用场景、可观察效果。参数定义3要素相同，但对象是参数的取值/不填情形。只将实际缺失与当前接口相关的项报告出来。

接口使用8要素采用固定映射，消除旧稿计数不一致：

| 要素 | 规则 | 所需内容 |
|---|---|---|
| 1 | RULE-04-01 | 相似接口差异和选取原则 |
| 2 | RULE-04-02 | 缺省配置、默认行为及适用条件 |
| 3 | RULE-04-03 | 生效条件、冲突和不生效场景 |
| 4 | RULE-04-04 | 环境、生命周期、系统能力/设备规格限制 |
| 5 | RULE-04-05 | 前提条件、前置操作及取得方式 |
| 6 | RULE-04-06 | 使用中建议、性能与常见问题 |
| 7 | RULE-04-07 | 配合接口、调用顺序及互斥关系 |
| 8 | 11.x/12.x 实现机制 | 为正确选择/使用所需的机制或关联说明 |

参数使用9要素：范围、单位、默认值/缺省效果、取值原则、生效机制、能力/设备限制、前置条件、使用建议、关联参数制约。一个“默认值缺失”只报一次，主维度12.x并附RULE-04-02，不按两套清单再加一条。

自包含描述范式（不是强制官方固定句式）：

- 可选参数：“未传入时采用…；当…时需显式传入…；越界时…”。未给实现证据不能擅自填省略内容。
- 废弃：“从API N起废弃；在满足…时使用X替代；差异为…”。N/X不可得标未验证，不编造替代。
- Promise/callback：“成功得到…后再…；失败通过…报告”。方式以声明为准，不能把void回调写成同步返回。

这些模板已包含必要资源正确性、完备性、易理解性检查，不要求另一个未附带的“资源模型”文件。语言风格可选配套写作技能；没有安装时不声称完成该专项全检。

## REST 分支（只在REST任务读取）

以给出的接口规格为源核对URI占位符、HTTP方法、鉴权、版本、请求参数、响应字段、状态码和错误结构。HTTP状态码与响应体业务码分开，不从“请求成功”推断所有业务分支成功。样例请求/响应应同场景一致；没有实际服务响应则行为正确性未验证。
