# 编辑增量与误报边界（源1.x–3.x的保留项）

本文件提取源规则中对代理决策有增量的约定，项目显式规范可覆盖默认风格。

| 规则 | 判定边界与证据 |
|---|---|
| 1.5 合规性 | 只有提供了比较文本、许可证或项目明令禁用术语时才给可定位风险；无来源不能从相似表达推断抄袭。 |
| 2.1 标题 / 2.2 层级 | 默认页内最多三级，但目标模板可允许四级；接口标识符中的连字符、斜杠或项目约定产品名不是机械禁字符。FAQ 标题标点也先服从模板。 |
| 2.3 段落 / 2.4 句子 | 仅在句式导致执行主体、条件或对象不明确时说明具体歧义；默认段落≤7行、句内逗号≤5是建议阈值，不是正确性门禁。 |
| 2.5 普通文档导航同步 | 新增或重命名普通指南时，按当前仓明确约定比对所在目录或上级 README/导航清单，确认新增入口和旧路径替换。正文出站链接正确不代表入站导航已同步；只有确定该导航为人工维护且应收录此文档时才报遗漏。自动生成、明确排除或缺少导航上下文时分别记不适用或未验证，不擅自要求新建导航。API Readme-CN 的既有来源检查结果可复用，同一遗漏只计一次。 |
| 3.1–3.7 语言 | 文档面向“开发者”，默认省略人称；步骤的条件、对象、结果必须能关联。数值/性能结论无数据时要求补证据，不替作者编数。 |
| 3.8 一致 | 账号访问用“登录”，并统一“单击、图像、阈值、重写”等约定；代码标识符和实际 UI 标签保留原字面值。 |

术语取证：同版本术语表 → 当前仓明确约定 → 文档内定义。首次全称缺失只有在全文/明确完整范围可检索时才能确认；仅有 PR hunk 时不能推定它是全文首现。缩略语 IP/MAC 等通用项不机械要求展开。缺术语表不妨碍指出同一文档把同一对象叫两个名称，但不能断言某个行业名称不合官方规范。

反例：将 API 名 `onClick` 改成中文以“统一语言”会损坏查阅；将已显示在 UI 的“点击”报告为必须改为“单击”可能与实机不一致。分别核对标识符和叙述文本，再适用 3.8。

完整性、通用清晰度、应用工程目录/命名、拼写与术语一致性检查引用既有技能；普通文档入站导航保留本地2.5判据；本文件只保留项目编辑约定和适用例外，不以源编号暗示已运行委派检查。
