# 内容元素、命名和交付（4.x、8.x–10.x）

只读取当前任务实际出现的元素。以下是迁入的默认约定，不能替代目标仓的模板与版本约定。

| 规则 | 检视决策 |
|---|---|
| 4.1 列表 / 4.2 表格 | 默认列表“- ”、层级≤2，表格建议≤9行、≤4列；先核对渲染效果和查阅需要，长参数表不因超阈值直接判不可用。缺省值、无、不涉及含义不同，不能统一替换。 |
| 4.3 图片 | 默认本地语义化图片路径；无版权依据只能标未验证。截图比较文字、组件与布局需实际可读图片，非 UI 示例不要求效果图，不强制所有截图1920×1080。 |
| 4.4 说明/注意/警告 | 约束会阻止操作或造成损失时，应在相关步骤前给出，而不是只放最终 FAQ；普通补充说明不升级为安全警告。 |
| 4.5 链接 | 先核对相对路径/锚点与中英文、版本目标，再谈在线有效性。网络不可用不等于断链；锚点由目标渲染器生成规则决定。 |
| 4.6 术语 | 使用结构与术语文件的证据顺序；无术语表不臆造官方用词。 |
| 4.7 单位 | 参数单位和取值边界优先核对 SDK/规格；排版单位风格不能覆盖真实参数字符串。 |
| 4.8 标点 / 4.9 转义 | 检查渲染后的表达，不机械给已有代码块/行内代码再转义；项目允许的 `<sup>` 版本角标不作为非法 HTML。 |
| 4.10 路径 | 区分设备路径、主机路径与项目相对路径；命令中的空格路径需要正确引用。项目相对路径不应强制补成本机绝对路径。 |
| 4.11 地址 / 4.12 个人信息 | 举例默认用私网及 example.com、掩码信息。真实服务入口、标准组织公共网址不属于伪造示例，不能因公网域名本身报错；个人信息须有实际内容证据。 |
| 8.x 命名与结构 | 按任务型/介绍型文档分别核对“目的—准备—步骤—验证”和“概念—范围—关联入口”；只有实际模板能决定必选章节。 |
| 9.x 交付 | 新增/变更 API 需与对应版本文档、changelog、导航关联；无交付清单时不声称发现全量遗漏。 |
| 10.x 目录 | 开发指南、reference/apis、图片资源和 README 路径以当前仓布局为准；不要把源仓常见目录当所有仓必须采用的结构。 |

示例：相对链接 `../apis/foo.md#bar` 无本地目标可核对→未验证；目标文件存在但给定渲染锚点列表没有 bar→4.5 可确认问题。前者不能报告成确定断链。
