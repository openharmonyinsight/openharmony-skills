# Unified diff 行号契约

解析 `diff --git`、`---`、`+++` 与 rename 元信息确定文件；带空格或转义的 Git 路径应正确解码，不能按空格盲目切分。`/dev/null` 表示新增或删除侧不存在。

每遇到 `@@ -old_start[,old_count] +new_start[,new_count] @@`，重置两侧计数器；省略 count 表示 1，count=0 表示空范围。

| hunk 内容前缀 | 记录 | 计数器推进 |
|---|---|---|
| 空格 | context | old 和 new 各 +1 |
| `-` | old 侧删除行 | old +1 |
| `+` | new 侧新增行 | new +1 |
| `\ No newline at end of file` | 元信息 | 不推进 |

文件头 `---`/`+++` 不属于 hunk 内容。hunk 内 `+++ text` 是内容为 `++ text` 的新增行，不能误当文件头。多 hunk 必须各自重置行号，检查声明计数是否与内容一致。若是 combined diff 或截断补丁，标记无法按本契约完整解析；获取普通 unified diff 或保留明确的未覆盖结论。二进制图片不适用文本 hunk 行号契约，转入下述文件级检视，不因缺少文本 patch 直接丢弃。

示例：

```diff
@@ -10,3 +10,3 @@
 context
-旧参数说明
+新参数说明
 context
```

新增问题定位 new:11；删除证据定位 old:11。仅删除 hunk 例如 `@@ -20,1 +19,0 @@` 中的旧行定位 old:20，即使新文件第 20 行是别的内容也不能借用。

删掉起始版本、权限或错误码前，检查同一改动是否移至其它位置、替换为链接或整个接口已移除；只在证据支持“必要内容丢失”时报告。行号定位用于报告，不等于平台 API 的评论 position；发布评论需按实际 API 文档转换且需要用户要求。

## 图片/图表文件级定位

`Binary files differ`、二进制 patch 或无文本 hunk 只说明没有可用文本行号。保留全部文件清单中的状态与 old/new 路径，读取可用图像并结合引用文档检查；未改动文档只是判断上下文。修改图应比较实际可读版本，删除图应检查引用目标。报告用“new 文件级：图中按钮标签”或“old 文件级：已删除图片的引用”定位，不制造 new:1/old:1。无法读取的版本及无法确认的文档关联单列未覆盖，不能将其计为符合。
