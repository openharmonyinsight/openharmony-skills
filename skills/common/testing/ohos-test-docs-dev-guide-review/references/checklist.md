# OpenHarmony 指南任务链与 G 规则

## 先用失败链路决定必要信息

| 读者遇到的断点 | 核对证据与反例 | 规则 |
|---|---|---|
| 同名API在目标工程无法使用 | 绑定SDK/API版本、Stage/其它应用模型及上下文，核对声明或项目约束；不能用另一版本IDE补全判当前示例错。 | G-02/G-11/G-14/G-18 |
| import/资源引用在片段外 | 追踪模块来源、路径/句柄/资源的取得方式以及宿主与示例的边界。已注明宿主提供不是“确定未定义”；完整工程遗漏必需资源才是操作断点。 | G-10/G-16/G-18/G-20 |
| 声明权限后仍不能操作 | 对照给定SDK的权限等级、声明位置及是否需要运行时授权；声明不等于已获授权，也不能要求所有权限一律弹窗。不要把Linux chmod/sudo作为鸿蒙权限通用恢复方法。 | G-11/G-17/G-20/G-22 |
| 调用顺序正确但运行环境不符 | 核对UIAbility/Worker等适用环境、生命周期、设备syscap及目标模型；只有SDK/规格明确禁止才报确定错误，不能按经验猜线程限制。 | G-02/G-11/G-15/G-17 |
| 展示代码但永远拿不到结果 | 从结果使用位置逆追Promise/callback成功路径，查初始化、状态更新和失败恢复；变量预先声明不证明异步结果已获得。 | G-10/G-17/G-20 |
| 按步骤完成却无法判断成功 | 寻找可观察结果与独立验证入口；若无需独立调测可在原步骤给成功状态，不机械追加无意义验证章节。 | G-19/G-21 |

## G 编号适用性与证据

| 编号 | 检视对象与判定 |
|---|---|
| G-01（28.1） | 大纲覆盖给出的用户任务；未提供用户旅程/资料需求模板时，以任务链判断现有大纲，模板遵循性记未验证，不要求不存在的外部模板。 |
| G-02（28.1） | 原理、约束与匹配实现/规格一致；缺实现不能断言实际行为。 |
| G-03（28.2） | 遵循目标项目写作约定；通用风格教学不在本技能展开。 |
| G-04/G-05（28.3.1/2） | 仅记录会改变操作对象/顺序/结果的明确歧义或语病，给出原句及两种可能解释。 |
| G-06（28.3.3） | SDK术语、接口名及首次解释以全文/目标术语表核对；片段不能证明全文首次缺失。 |
| G-07（28.3.4） | 对照同类信息与复杂关系是否有足够支撑；图不是每个步骤的硬要求。 |
| G-08（1.5） | 相似性/来源风险须有对照文本、许可证或项目禁用术语清单；证据不足记未验证，不推断抄袭。真实服务域名不等于示例泄漏。 |
| G-09（28.4） | 典型场景来自给出的需求、API生命周期或项目验收范围；不能把任意设想场景算承诺遗漏。 |
| G-10（28.5） | 从输入到结果的操作链闭合，工程/依赖/资源取得方式可追踪；依据上表定位实际断点。 |
| G-11（28.6） | 影响本任务的版本、能力、权限、环境约束已交代；没有规格不能凭空加限制。 |
| G-12（28.7.1） | 标题能区分用户任务；不因用了功能名就直接判不合格。 |
| G-13（28.7.2，可选） | 多分支/长任务需流程辅助；默认不因缺流程图阻断必选项。 |
| G-14（28.7.3，可选） | 专门全量核对接口说明；若现有必选步骤明显违反已给签名，仍可按G-02/G-20报告，不因本项可选忽略已知错误。 |
| G-15（28.8.1） | 步骤主体、触发条件、位置与结果能落到目标工程和生命周期。 |
| G-16（28.8.2） | 示例不依赖未声明输入或真实私人信息；规格/API名不是任意改写的“敏感内容”。 |
| G-17（28.8.3） | 分支选择、关键前提及不可恢复操作的提醒必须在使用点可见，避免只在结尾解释。 |
| G-18（28.8.4） | 片段放入声明的宿主上下文可用；没有宿主工程时编译记未验证，不能推断失败。 |
| G-19（28.8.4） | 完整示例有可复现环境与预期结果；截图属于提供的证据，不代替实际运行。 |
| G-20（28.8.4） | 自包含示例核对：匹配SDK签名/版本、依赖与变量来源、资源/权限/上下文、异步成功后使用结果、失败处理与资源释放、展示效果一致（如适用）。不依赖外部“完整代码质量清单”。 |
| G-21（28.9.1，可选） | 存在独立调测操作时有入口及预期判据，否则可不适用。 |
| G-22（28.9.2，可选） | 对给定的常见故障说明现象→取证→原因区分→针对性恢复→复验，不用泛化提权代替权限诊断。 |

默认18个必选规则、4个可选规则；G-04/G-05虽然合并展示仍是两个独立统计单位。部分实例验证成功、其余缺条件不能算整条满足，按入口统计契约记未验证；若已有一个实例确定违规则记不满足。

示例：`guide.md:30`直接调用`save(targetPath,payload)`，已给规格要求先取得路径并授权，而文档均未交代→G-10/G-11同一前置链路断点，按根因合并并列证据；建议补输入来源、授权与失败出口。只有“宿主提供readConfig”的片段且没有工程→G-18未验证，G-19不适用，不能报编译失败。
