# L2_Filter - 分层过滤模块

## 模块概述

分层过滤模块是 XTS 问题分析的核心阶段，采用**分层过滤模型**精准定位日志切片，而非"关键字盲扫全量日志"。

## 核心设计理念

### 现状问题（关键字盲扫）

- 解密**整个** hilog 日志（可能 29692 行）
- 对 80 条规则的 keyword，逐条在**全量日志**中 grep
- **噪音高**：跨子系统日志混在一起，易误判
- **多义易错**：ArkUI 崩溃栈含"App died"字样会被误判为"元能力闪退"

### 优化方案（分层过滤）

采用**分层过滤**而非"硬过滤丢弃"：
- 时间窗外的日志 → 硬丢弃（噪音↓）
- 时间窗内 domain 不匹配的日志 → 备用集暂存（不漏判）
- PID/TID 优先扩展 → 抓同线程因果链（比位置窗口更强）

## 分层过滤流程

### 分层过滤流程图（可视化）

```
输入：全量hilog日志（可能29692行）
    │
    ▼
┌─────────────────────────────────────┐
│ Layer 1: 时间窗硬过滤                 │
│ - 提取用例时间窗[T_start, T_end]       │
│ - 保留时间窗内日志                     │
│ - 丢弃时间窗外日志（噪音↓）             │
└─────────────────────────────────────┘
    │
    ▼ 时间窗内日志（约500-2000行）
    │
┌─────────────────────────────────────┐
│ Layer 2: domain分组（软过滤）          │
│ - 主分析集：domain匹配失败用例引用API   │
│ - 备用集：domain不匹配的行（暂存）      │
└─────────────────────────────────────┘
    │
    ├─→ 主分析集（约50-200行）
    │       │
    │       ├─→ 规则命中？→ ✅ 输出到L3_Report
    │       │
    │       └─→ 规则0命中？→ ⚠️ 触发主→备用扩展
    │               │
    │               ▼
    │               扩展到备用集（时间窗内全量）
    │               │
    │               └─→ 输出到L3_Report
    │
    └─→ 备用集（暂存，不立即丢弃）
            │
            ▼ 等待主→备用扩展触发
    │
┌─────────────────────────────────────┐
│ Layer 3: 渐进式扩展（上下文补充）       │
│ - P1：同(PID,TID) - 同线程因果链       │
│ - P2：同PID不同TID - 同进程跨线程      │
│ - P3：位置窗口前/后各20行 - 上下文兜底 │
└─────────────────────────────────────┘
    │
    ▼
输出：分层过滤后的日志切片
    │ - 带分层来源标记：[主]/[P1]/[P2]/[P3]
    │ - 分层命中统计
```

### Layer 1: 时间窗过滤（硬过滤）

**时间窗来源**：
- 优先：hilog `[Hypium]start/[Hypium][fail|end]` 标记（设备时间）
- 回退：module_run.log 的 `[Listener]` 时间戳（PC 时间）

**操作**：
```bash
# 提取时间窗内的日志
grep -n "Hypium" decrypted/*.txt | grep "start running case 'SUB_..._3100'"
grep -n "Hypium" decrypted/*.txt | grep "\\[fail\\]SUB_..._3100"
```

**输出**：
- 时间窗：[T_start, T_end]
- 时间窗外 → 丢弃

### Layer 2: domain 分组（软过滤）

**主分析集** = domain 匹配失败用例引用 API 的行
**备用集** = domain 不匹配的行（暂存，不立即丢弃）

**操作**：
```bash
# 主分析集：匹配 domain
grep -E 'C0031[0-9a-f]{2}/|C0013[0-9a-f]{2}/' decrypted/*.txt

# 备用集：不匹配 domain（时间窗内）
grep -v -E 'C0031[0-9a-f]{2}/|C0013[0-9a-f]{2}/' decrypted/*.txt
```

### Layer 3: 渐进式扩展

**扩展策略**：

① **主→备用扩展**（触发条件：主分析集 0 条规则命中）
```bash
# 主分析集未命中 → 扩展到备用集（时间窗内全量）重跑
```

② **上下文扩展**（锚点 = 主分析集全部行的 PID/TID 对）

| 优先级 | 扩展方式 | 含义 |
|--------|----------|------|
| P1（最高） | 同 (PID, TID) | 同线程因果链（被其他线程日志打断的同一栈） |
| P2 | 同 PID、不同 TID | 同进程跨线程（IPC/UI回调） |
| P3（兜底） | 位置窗口 前/后各 20 行 | 上下文兜底 |

**操作示例**：
```bash
# 提取 PID/TID
grep -n "C00310" decrypted/*.txt | awk '{print $3, $4}'  # PID, TID

# P1 扩展：同 (PID, TID)
grep -n "PID TID" decrypted/*.txt

# P2 扩展：同 PID、不同 TID
grep -n "PID" decrypted/*.txt

# P3 扩展：位置窗口
# 根据主分析集行号，提取前/后各 20 行
```

## 独立通道：cppcrash

**cppcrash 文件**：全量直送 SO 崩溃栈分析（绕过所有过滤）

```bash
# cppcrash 不受 domain 过滤影响
# 全量送第6步 SO崩溃栈分析
cat cppcrash.log
```

## 分层过滤参数表

> ⚠️ **强制要求**：报告生成时必须在"时间窗提取"章节展示分层过滤参数表（参考格式见下）

### 参数表（固定格式）

| 参数 | 值 | 说明 |
|------|-----|------|
| 时间窗来源 | hilog [Hypium] 标记优先 | 提供设备时间 + 精确行号，更准确 |
| 时间窗容差 | ±2s | PC时间与设备时间对齐容差（回退策略时使用） |
| 时间窗外行处理 | 硬丢弃 | 噪音↓，避免跨子系统日志混在一起 |
| 时间窗内domain不匹配行 | 备用集暂存（兜底可用） | 不漏判，允许主→备用扩展 |
| 主→备用扩展触发条件 | 主分析集0条规则命中 | 主分析集未命中时，扩展到备用集（时间窗内全量）重跑 |
| domain过滤策略 | 主+备 | 先过滤主分析集（精准），无命中则扩展备用集（兜底） |
| 上下文扩展锚点 | 主分析集全部行的PID/TID对 | 抓同线程因果链，比位置窗口更强 |
| PID/TID扩展优先级 | P1>P2>P3 | 优先抓同线程因果链（P1），再扩展同进程（P2），最后上下文兜底（P3） |
| 位置窗口大小 | 前/后各20行 | 上下文兜底范围，避免关键信息丢失 |
| PID/TID与位置窗口关系 | 并存（都纳入，标注来源） | 确保证据链完整性 |
| cppcrash文件处理 | 独立全量通道，不过滤 | 崩溃召回不受domain过滤影响 |

### 参数值选择依据

**时间窗来源优先级**：
- hilog [Hypium] 标记：设备时间 + 精确行号 → **优先**
- module_run.log [Listener]：PC时间，需对齐 → **回退**

**时间窗容差±2s**：
- hilog（设备时间）与module_run.log（PC时间）可能存在时间偏差
- ±2s容差可覆盖大多数场景

**domain过滤策略主+备**：
- 主分析集：精准匹配失败用例引用API的domain → **噪音↓**
- 备用集：兜底，避免漏判（如跨子系统调用、日志domain未登记）

**PID/TID扩展优先级P1>P2>P3**：
- P1（同线程）：最强，能抓同线程因果链（如函数调用栈）
- P2（同进程）：中等，能抓IPC/UI回调等跨线程交互
- P3（位置窗口）：兜底，确保关键信息不丢失

**位置窗口大小前/后各20行**：
- 经验值，覆盖大多数上下文场景
- 太小（<10行）可能遗漏关键信息
- 太大（>50行）噪音增加

## 分层来源标记

每行摘录前标注来源，让证据链可追溯：

| 标记 | 含义 | 优先级 |
|------|------|--------|
| `[主]` | 主分析集（domain 匹配失败用例引用 API） | 最高（基础） |
| `[P1]` | 同 (PID, TID) 扩展（同线程因果链） | 高 |
| `[P2]` | 同 PID、不同 TID 扩展（同进程跨线程） | 中 |
| `[P3]` | 位置窗口前/后各 20 行（上下文兜底） | 低 |

## AI 使用方式

### AI 主动过滤

AI 应按照以下步骤主动执行分层过滤：

1. ✅ 提取时间窗（L0_PreAnalyze 的输出）
2. ✅ 解析失败用例的 API→domain 链路（L0_PreAnalyze 或用户提供）
3. ✅ 执行 Layer 1 时间窗过滤
4. ✅ 执行 Layer 2 domain 分组
5. ✅ 执行 Layer 3 渐进式扩展（如需）
6. ✅ 标注分层来源标记

## 输出产物

供 L3_Report 使用：
- 分层过滤后的日志切片
- 分层来源标记（[主]/[P1]/[P2]/[P3]）
- 分层命中统计（主: X行 | P1: Y行 | P2: Z行 | P3: W行）
- 扩展触发提示（如主分析集 0 命中）

## 关键改进说明

- **时间窗硬过滤**：剔除与本次失败无关的日志（噪音↓）
- **domain 软过滤**：主分析集精准，备用集兜底（不漏判）
- **PID/TID 优先扩展**：比"前/后 N 行"位置窗口更强——能抓同线程因果链和同进程跨线程
- **崩溃通道独立**：cppcrash 文件全量送第6步，崩溃召回不受 domain 过滤影响
