# 可行性分析强制规则（判定细则）

> 本文件由 `ohos-req-feasibility-analysis` SKILL.md「强制规则」引用。生成 `02-feasibility.md` §2-§6 各章节时按需加载，逐条判定。
> SKILL.md 保留 5 条顶层不变式（核心红线），详细判定口径在此文件。

## 1. 技术判断证据约束

- 技术判断必须有源码、文档、PoC 或 Owner 证据，否则标记待验证。
- **代码事实验证**：§2.1 优先基于主 Session 提供的 `{kb_precheck_path}` 证据包。证据包未覆盖的引用标记"待 Phase 2 验证"，不得虚构。
  - **Fallback**：如需补充验证，使用 Read 工具读取实际代码；Read 不可用时降级为 `warn`（标注"未实地验证，引用来源：预检证据包"），不硬 fail。

## 2. 启动前软前置确认

- 必须存在 `{docs_dir}/_draft/feasibility-inputs.md`，且其中记录了用户提供的实际资料，或用户明确确认不额外提供资料。未完成确认时不得生成 `02-feasibility.md`。

## 3. 证据受限显式标注

- 当用户确认不额外提供本地关键代码仓路径或前置依赖资料时，`02-feasibility.md` 必须在「输入证据状态」和相关代码/接口章节标注证据受限，不得写成源码已验证或接口已确认。

## 4. 候选路径与单方案降级

- 至少识别 2 个可验证技术路径；有多个路径时保持中立描述。
- 单方案降级规则：仅当客观上只有一条可行路径时允许单方案，但必须标注 `warn`（条件项："仅单方案，需写明不可行证据"）并写明其他路径不可行的证据、以及条件变化后的重新决策规则。**禁止硬 fail 单方案**——避免迫使 AI 虚构垃圾方案凑数。

## 5. 选型推荐禁令（详见 SKILL.md NEVER §1）

- feasibility 不允许出现"推荐"列、"建议选择XX方案"、"XX方案最优"等决策倾向性表述。方案选型决策 exclusively 属于 03-arch-decision-record.md，由用户提供。每个方案只给出可行性判断（✅可行/⚠️有条件可行/❌不可行）和事实依据，不做推荐排序。

## 6. 按方案独立估算工作量

- 每个候选方案必须独立给出代码行数估算和人月折算，不允许只给单一总量。必须输出"各方案工作量对比汇总"表。03-arch-decision-record.md 的方案成本对比依赖此数据。
- 工作量估算必须按统一标准：500行≈1人月；测试=开发×0.3；设计=开发×0.1；UX=开发×0.1。不使用其他估算标准。

## 7. 多子能力分开分析

- 当需求包含多个独立子能力时，`02-feasibility.md` 必须先按子能力分别输出候选路径、依赖、工作量、风险和可行性结论，再输出组合路径判断。工作量表和风险表必须带子能力归属。

## 8. 结论章节填写约束（§6 可行性结论）

- **只保留各方案可行性**：§6 只判断各方案可行性（方案可行即需求可行，不单列需求维度）；选型决策见选型推荐禁令。
- **关键依据用锚点链接**：涉及章节引用处以 `[§章节名](#锚点)` 跳转（锚点按标题生成，如 `## 2. 技术可行性` → `#2-技术可行性`），不写纯文本。
- **风险直接陈述**：风险只写风险本身与缓解方案，取值 `✅无风险 / ⚠️风险可控 / 🔴高风险`，**不指向后续环节**（如"待 Phase 2""见前置条件"）；后续判断由下游文档（03-arch-decision-record.md / feature.md）承载。

## 9. 性能与竞品

- 性能暂无指标时记录"暂不设指标"和后续观测方式。
- 竞品仅在能提供决策证据时纳入。
- **竞品参考必须给出链接出处**：§3 竞品参考表每条记录必须填写「来源链接」列（官方文档URL/源码仓库URL/技术博客URL/标准规范URL）。无出处链接的竞品记录视为不可信证据，不得作为可行性判断依据，应标记为"来源不可追溯"并从结论引用中排除。

## 10. 可视化与 GAP 分析

- 每个候选路径必须有 Mermaid 可视化图：至少包含 1 个流程图 + 1 个时序图（跨进程 IPC 场景）；类图为可选但推荐。纯文字描述的"改动链路"不足以支撑决策。
- **GAP 分析必须包含关键接口签名和调用链路**：不能只列文件名和行号，要展示接口参数、返回值、调用方向（谁调谁）。

## 11. 章节禁令

- **不生成 ROI 章节**：模板已去除 ROI 分析章节，只保留收益量化（详见 SKILL.md NEVER §2）。
- **自审清单不写入文档**：自审结果输出到控制台回传摘要（详见 SKILL.md NEVER §5）。
