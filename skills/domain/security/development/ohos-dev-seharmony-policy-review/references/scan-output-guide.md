> **Ref semantics and boundary behavior**: **any branch ref** — local short name (`feature`), remote-tracking (`origin/feature`), or full ref (`refs/heads/feature`, `refs/remotes/origin/feature`) — auto-resolves the merge-base (trying `origin/master`, `origin/main`, `master`, `main` in order) and scans the net diff; scanning only the tip commit would miss earlier commits. Bare commits, tags and rev expressions (sha, HEAD, sha~2) stay tip-commit scans; a detached SHA never surfaces other commits' changes. S4 definition lookups and S17 whole-file checks bind to the scanned target's tree (`git grep <tree>` / `git show <target-ref>:<file>`); stdin binds no tree — those items stay pending and must never fall back to the current checkout. When not resolvable, the script errors and asks for `<base>..<head>`. An empty net diff (added then reverted) exits 1 with an empty-diff message — no false positives. S23 multi-line macro scope is tracked across context+added lines and resets at hunk/file boundaries; plain allows after a macro close (`')`) are not misreported. S17 avc proximity is judged per hunk independently. Exit codes: 0 = completed (does not mean no violations); 1 = empty diff; 2 = input/usage error (unresolvable ref or merge-base). Regression gate (two layers): `python3 scripts/run_evals.py` runs all machine_checks + built-in git regressions (branch-ref spellings, detached SHA, two-commit branch, S4 checkout-invariance, empty net diff) + grader self-test + full-CLI negative self-test (corrupted reports must exit non-zero) and must print `SCANNER REGRESSION PASSED`; `python3 scripts/run_evals.py --reports evals/reports` additionally structurally validates every golden report (unique rows, single-enum statuses, sign-aware ROM/A/D/M cross-checked against the scanner, status-to-disposal forcing) and grades every assertion's grader rules — must print `ALL GATES PASSED`.
