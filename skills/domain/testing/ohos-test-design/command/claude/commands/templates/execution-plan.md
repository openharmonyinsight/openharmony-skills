## 双轨并行关系

> 标准及以上复杂度：Dev Track 和 Test Track 并行推进，通过 AC 编号同步。

```
Dev Track                              Test Track
─────────                              ──────────
TASK-1 (实现功能)  ←── AC-1.1 ──→  TASK-T1 (验证功能)
TASK-2 (实现功能)  ←── AC-1.2 ──→  TASK-T2 (验证功能)
TASK-3 (实现排序)  ←── AC-3.1 ──→  TASK-T3 (验证排序)
```

## Task 粒度原则

- 每个 Task 对应一个可独立验收的最小能力闭环
- 两项改动共享同一规则上下文和同一最小验证闭环 → 合并为一张 Task Card
- 文件范围、验证闭环和风险边界足够分离 → 拆分为多张 Task Card
- 简单变更：1-2 张 Task Card；复杂变更：按接线层/规则层/恢复层拆分
- 每个 Task 是可独立验证的最小能力闭环，不按代码行数或预估时间拆分

## 禁止项

执行计划和 Task 不得出现以下内容：

- [ ] 没有 TBD / TODO / 占位符
- [ ] 没有"根据需要实现""酌情处理"等模糊指令
- [ ] 没有跨 Task 隐式依赖（依赖必须显式声明在前置依赖列）
- [ ] 没有要求 Agent 自行寻找未列出的上下文文件
- [ ] 没有无验证方式的 AC
- [ ] 没有"与 Task-N 类似""参考 Task-N 实现"等引用（每个 Task 自包含）
