# 阶段5：验证与导出规则

## NEVER（执行约束）

### 流程执行类
- NEVER 以下执行约束失败后不进行修复——未满足约束必须修复后才可pass，修复失败（＞2次）后人工确认是否跳过
- NEVER 生成xlsx文件失败后跳过导出步骤——输出失败后必须重新生成
- NEVER 生成全部文件后不进行检查——必须检查全流程文件输出是否正确

### P0门禁类
- NEVER P0问题存在时导出——P0问题=0才可导出

### 格式规范类
- NEVER test_cases导出csv或其他非xlsx格式——仅允许导出xlsx格式（md格式保留）
- NEVER xlsx列数≠18——必须使用18列导出（A-R列）
- NEVER xlsx存在乱码——必须UTF-8编码正确，无乱码
- NEVER xlsx行数≠md用例数+1——必须保证MD与XLSX用例数一致
- NEVER xlsx必填字段为空单元格——必须完整填写
- NEVER xlsx与md用例级别不一致——必须保持一致（P0→level 0, P1→level 1）

### 内容规范类
- NEVER xlsx中用例名称、预置条件、测试步骤、预期结果列含内部追溯ID——内部ID仅在"备注"列用于追溯
- NEVER xlsx预期结果仅依赖"接口返回成功"——存在可外观测生效效果时，必须包含外部可观测证据

### 清理类
- NEVER 在导出xlsx前清理临时文件——xlsx导出成功后必须立即删除临时文件和中间JSON文件

## 执行逻辑

### 第一步：验证

1. 读取 test_cases.md 和 test_point_design.md
2. 检查 phase5_export.py 脚本是否已自动生成 validation_report.md
3. 若脚本已生成且内容完整 → 直接使用，跳过AI验证生成
4. 若脚本未生成或生成失败 → AI按下方四维度评分格式自行生成 validation_report.md（降级策略）
5. 检查 P0 问题数

### 第二步：P0 门禁

- P0 问题 = 0 → 继续导出
- P0 > 0 → 自动修复（修复后重新验证），最多 1 轮
  - 修复方式：修正 test_cases.md 中 P0 问题涉及的用例
  - 修复后重新验证，若 P0 仍 > 0 → 报告失败，停止处理

### 第三步：导出与清理（强制执行）

**导出方式：直接调用 Python 脚本，不读脚本源码、不做字符串替换、不拷贝脚本。**

**脚本路径**：`{skill_dir}/assets/phase5_export.py`，其中skill_dir为ohos-design-test-coordinator技能目录（可通过glob SKILL.md定位）。

**用例编号起始值：** 从启动阶段传递的 USER_START_ID 使用（已在启动阶段询问并校验）

**导出执行步骤（仅需 1 条 Bash 命令）：**

```bash
python {技能目录}/assets/phase5_export.py --output {输出目录} --start-id {USER_START_ID或省略} --testpoint {test_point_design.md路径}
```

- 若 USER_START_ID 为 None，省略 `--start-id` 参数（脚本使用默认值 `case_id_temp_001`）
- 若 USER_START_ID 有值，传入 `--start-id {值}`
- `--testpoint` 参数可选，传入test_point_design.md路径可启用覆盖率检查功能

**解析脚本输出：**

脚本输出一行 JSON，格式如下：
```json
{
  "status": "success",
  "file": "/path/to/test_cases.xlsx",
  "cases": 42,
  "rows": 43,
  "empty_cells": 0,
  "file_size": 28512,
  "warnings": []
}
```

解析规则：
- `status == "success"` → 导出成功，**立即执行清理**
- `status == "error"` → 导出失败，读取 `message` 字段排查

**清理临时文件（强制执行）：**

**必须删除以下临时文件和目录（清理失败不阻塞流程）**：

| 文件/目录 | 说明 | 产生脚本 |
|----------|------|---------|
| `{输出目录}/batches_phase2/` | Phase2分批临时目录 | Phase2 Agent |
| `{输出目录}/batches_phase4/` | Phase4分批临时目录 | Phase4 Agent |
| `{输出目录}/batches/` | 通用批次目录 | Phase2/Phase4 Agent |
| `{输出目录}/temp/` | 临时工作目录 | 多阶段共用 |
| `{输出目录}/testing_technology.json` | Phase2测试技术中间件 | phase2_testing_technology.py |
| `{输出目录}/coverage_result.json` | Phase2覆盖率检查中间件 | phase2_testpoint_utils.py |
| `{输出目录}/phase2_*.json` | Phase2所有中间JSON文件（glob模式） | phase2_adversary.py 等 |
| `{输出目录}/phase4_*.json` | Phase4所有中间JSON文件（glob模式） | phase4_adversary.py 等 |
| `{输出目录}/validate_result.json` | Phase4校验结果中间件 | phase4_testcase_utils.py |

**清理规则**：
- 使用 glob 模式匹配清理 `phase2_*.json` 和 `phase4_*.json` 所有中间文件（覆盖 phase2_coverage_*.json、phase4_adversary.json 等所有命名）
- 仅删除上述明确列出的临时文件
- 清理失败不阻塞流程，记录告警到摘要

**注意**：以下文件应保留，避免误删：
- knowledge_match.md（知识库匹配结果，最终输出件）
- adversarial_report.md（对抗评估报告，最终输出件）
- Phase3生成的Demo文件（demo_design.md、TestDemo/、demo_code_manifest.md）
- timing.json（计时报告数据源，完成后需追加 pipeline_completed_at）
- tasks/（含 task_checkpoints/ 审计快照，task-manager 禁止删除）
- 用户自定义文件

**失败处理：** 脚本执行失败（status=error 或 Bash 返回非零）→ 重新执行（最多2次），仍失败则记录到摘要

### 第四步：一致性检查

对比 test_cases.md 和脚本 JSON 输出：

| 检查项 | 验证方式 |
|--------|---------|
| 用例数量 | 统计 MD 中 `### TC-` 标题数 == JSON `cases` 字段 |
| 空值告警 | JSON `warnings` 列表为空 |
| 文件完整性 | JSON `file_size > 0` |

**说明：用例编号不做校验（MD原始编号与Excel生成编号格式不同）**

**test_cases.md格式引用说明：**

- 汇总表格式：见phase4_testcase.md（列顺序必须与脚本解析逻辑一致）
- 用例详细格式：见phase4_testcase.md（用例标题必须使用三级标题 `### TC-XXX`）
- phase5_export.py解析逻辑：查找 `### TC-` 标题提取用例详情，汇总表按固定列索引提取字段

不一致处理：重新执行导出脚本（最多2次），仍不一致则记录到摘要

**不一致记录示例：**

```
用例数量：期望X个，实际Y个，缺少Z个
空值告警：第5行 测试步骤为空
```

## 验证维度与评分

| 维度 | 权重 | 检查内容 |
|------|------|---------|
| 完整性 | 30% | 测试点覆盖率100%、字段无空值、验证完整性（预期结果验证到外部可观测效果） |
| 正确性 | 25% | 预期结果与测试意图匹配、错误码正确、规则验证标注完整、验证完整性原则应用正确 |
| 可执行性 | 20% | 步骤描述清晰含数据、预置条件明确、控件引用使用可见标签格式（非裸控件ID） |
| 覆盖率 | 25% | 被测场景/参数规格/字段关联图谱/验证映射覆盖/非功能需求/测试点覆盖统计 |

**验证完整性原则检查**：
- 存在可外观测生效效果的用例，预期结果必须包含外部可观测证据（进程状态、系统日志、UI变化、持久化数据）
- 逻辑终点即为可观测输出的用例，验证该输出即为充分
- 仅依赖"接口返回成功"等手段层反馈作为唯一预期 → 扣5分

### Excel样式

- 首行冻结（A2）
- 表头：深蓝背景(#1F4E79)白色粗体Arial
- 数据：Microsoft YaHei 10pt，自动换行
- 用例级别颜色：level 0浅红(#FFC7CE)、level 1浅黄(#FFEB9C)、level 2浅绿(#C6EFCE)
- 行高按内容动态计算
- 自动筛选覆盖全部数据行
- D~J列设置下拉列表数据验证

### 用例编号规则

- 起始值由用户一次性输入（如 `TC-001`），不允许包含 `%`
- 未输入时，默认使用 `case_id_temp_001` 开始
- 编号自动递增：`case_id_temp_001` → `case_id_temp_002`...

### 数据清洗规则

1. **用例名称（B列）**：自动过滤单引号 `'`，避免Excel公式错误
2. **用例编号（C列）**：验证起始值不含 `%`，若包含则拒绝导出并提示用户重新输入
