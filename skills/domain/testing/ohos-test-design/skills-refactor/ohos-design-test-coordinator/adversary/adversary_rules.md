# 对抗评估规则

> 核心目标：保证测试充分性
> **执行模式**：脚本固化流程（含初步识别） + AI语义校验（混合模式）

## 一、phase2测试点对抗

**脚本调用**：
```bash
python {技能目录}/../assets/phase2_adversary.py \
  --testpoint {输出目录}/test_point_design.md \
  --requirement {输出目录}/requirement_analysis.md \
  --knowledge-match {输出目录}/knowledge_match.md \
  --output {输出目录}/phase2_adversary.json
```

### 脚本固化部分

| 功能 | 脚本输出 | 说明 |
|-----|---------|------|
| 前置数据锁定 | data_lock | 测试点总数、测试对象测试点数、被测场景总数、API总数、验证映射总数 |
| 前置约束检查 | constraint_check | inner接口违规测试点 |
| 测试对象覆盖率 | coverage.test_object | 风险加权覆盖率(P0×4,P1×3,P2×1,P3×0.5)×0.7+API风险加权×0.3，得分=覆盖率×40分；经验覆盖率修正：modifier=max(0.7,1-0.3×(1-经验覆盖率)) |
| 测试对象关键场景 | key_scenarios.test_object | P0(8+8)/P1(6+6)/P2(4)/P3(2)基础分+深度分，得分=评分百分比×45分 |
| 测试对象变异体 | mutation.generate.test_object_mutations | P0(4-5类)/P1(2-3)/P2(1-2)/P3(1类)差异化生成 |
| 变异体过滤 | mutation.generate.skipped_fixed_values | 权限2750、属组3823等固定值不生成±1变异 |
| 测试对象变异杀死 | mutation.kill.test_object | 风险加权杀死率(P0×4,P1×3,P2×1,P3×0.5)，得分=杀死率×15分 |

### AI语义校验部分

| 功能 | AI输入 | AI输出 | 说明 |
|-----|-------|-------|------|
| 测试对象覆盖语义校验 | coverage.test_object | 补充遗漏/移除误判 | 测试对象P0-P3全量校验+经验[必测]/无标注(最深层级)遗漏补充 |
| 深度覆盖语义校验 | key_scenarios.test_object.tp_details | 补充遗漏/移除误判 | 仅测试对象测试点参与深度判断 |
| 测试对象变异语义相似 | mutation.kill.test_object.alive_mutations | 语义杀死 | 测试意图≈变异目标 |

### 三维度评分

| 维度 | 权重 | 计算方式 |
|------|------|---------|
| 需求覆盖率 | 40分 | 风险加权覆盖率×40 |
| 关键场景评分 | 45分 | P0(8+8)/P1(6+6)/P2(4)/P3(2)，评分百分比×45 |
| 变异杀死率 | 15分 | 风险加权杀死率×15 |

**达标阈值**：总分≥80分（三维度加权求和）

**风险加权权重**：P0=4, P1=3, P2=1, P3=0.5（覆盖率/杀死率均使用）

**风险等级来源**：knowledge_match.md§1.1交付推断 + testing_technology.json units字段

### 测试经验覆盖验证（§2验证点纳入覆盖率维度）

**验证点采纳规则**（[必测]/[选测]为附加标注，无标注≠可跳过）：

| 采纳层级 | 标注 | 测试对象采纳 | 说明 |
|---------|------|------------|------|
| 最深层级 | 无标注 | 直接采纳（视为必测） | 无标注时全部验证点视为必测 |
| 最深层级 | [必测] | 直接采纳 | 明确标注必测 |
| 最深层级 | [选测] | 语义匹配采纳 | 仅测试对象按需采纳 |
| 父层级 | 无标注 | 语义匹配（选测逻辑） | 无标注按选测逻辑 |
| 父层级 | [必测] | 直接采纳 | 明确标注必测 |
| 父层级 | [选测] | 语义匹配采纳 | 仅测试对象按需采纳 |

**历史频率→风险等级映射**：高→P0, 中→P1, 低→P2

**经验覆盖率修正**（纳入覆盖率维度评分）：
- 覆盖率得分 × experience_modifier
- modifier = max(0.7, 1 - 0.3 × (1 - 经验覆盖率/100))
- 经验覆盖率100% → modifier=1.0（无修正）
- 经验覆盖率0% → modifier=0.7（覆盖率得分降低30%）
- 经验覆盖率50% → modifier=0.85（覆盖率得分降低15%）

**循环规则：**
- 最多3轮对抗
- 总分<80分→补充测试点→重新调用脚本
- 编号规则：TP-ADD-{NNN}
- 补充优先级：P0遗漏优先→P1→P2(≤3条)→P3(≤2条)
- 测试对象遗漏→P0-P3全量补充

## 二、关键场景评分细则

### 脚本初步识别

脚本输出key_scenario_details，包含：
- 各场景类型的测试点总数
- script_depth_cover_count：脚本基于关键词识别的深度覆盖数量
- script_depth_cover_tps：脚本识别的深度覆盖测试点ID列表
- tp_details（供AI语义校验）

### 评分配置（简化）

| 场景类型 | 基础分 | 深度分 | 满分 | 说明 |
|---------|-------|-------|------|------|
| 边界场景 | 5分 | 5分 | 10分 | 每个测试点基础5分，深度覆盖+5分 |
| 异常场景 | 5分 | 5分 | 10分 | 每个测试点基础5分，深度覆盖+5分 |
| 竞态场景 | 5分 | 5分 | 10分 | 每个测试点基础5分，深度覆盖+5分 |
| 特殊场景 | 5分 | 5分 | 10分 | 每个测试点基础5分，深度覆盖+5分 |
| 数据持久化 | 5分 | 5分 | 10分 | 每个测试点基础5分，深度覆盖+5分 |
| 状态转换 | 5分 | 0分 | 5分 | 基础覆盖即可，无深度分 |
| 组合场景 | 5分 | 0分 | 5分 | 基础覆盖即可，无深度分 |

### 脚本初步识别关键词

| 场景类型 | 关键词列表 |
|---------|-----------|
| 边界场景 | 边界附近、边界±1、临界值、边界极值、±1、±5%、极限、极端 |
| 异常场景 | 异常恢复、重试、修复、清理、失败后、恢复验证、异常后、恢复正常 |
| 竞态场景 | 并发边界、竞态条件、时间窗口、同时、临界、并发上限、竞态 |
| 特殊场景 | 权限隔离、跨用户、跨应用、安全深度、权限校验失败、隔离验证 |
| 数据持久化 | 写入后读取、持久化验证、数据恢复、写入验证、持久化 |

### AI语义校验标准

脚本关键词匹配可能遗漏或误判，AI需进行语义校验：

| 校验类型 | AI判断标准 | 处理方式 |
|---------|-----------|---------|
| 遗漏补充 | 测试意图满足深度条件但无关键词匹配 | 增加深度分（+5分） |
| 误判移除 | 有关键词匹配但测试意图不满足深度条件 | 移除深度分 |

**深度覆盖语义判断标准**：
- 边界场景深度：测试意图是验证边界值附近的系统行为
- 异常场景深度：测试意图是验证异常发生后系统的恢复能力
- 竞态场景深度：测试意图是验证并发场景的边界条件
- 特殊场景深度：测试意图是验证安全/权限的深度隔离
- 数据持久化深度：测试意图是验证数据写入后的读取一致性

### 计算公式

```
关键场景评分 = (脚本基础分 + 脚本深度分 + AI补充深度分 - AI移除深度分) / 有效满分 × 100

脚本基础分 = 各场景类型测试点总数 × 基础分(5分)
脚本深度分 = script_depth_cover_count × 深度分(5分)
有效满分 = 各场景类型测试点总数 × 满分(10分)
```

## 三、变异测试细则（含固定值过滤）

### 固定值变异过滤

以下参数为固定常量，不生成±1变异：
- 权限：2750（固定权限值）
- 属组：3823（固定属组值）

脚本输出mutation.skipped_fixed_values记录被过滤的固定值参数。

### 脚本输出

脚本输出mutation，包含：
- mutation_total：变异体总数
- skipped_fixed_values：被过滤的固定值变异列表
- exact_killed：精确覆盖杀死列表（权重60%，直接杀死）
- range_killed：范围覆盖杀死列表（权重30%，±10%）
- alive_mutations：存活变异体列表（供AI判断语义相似）

### AI语义相似判断

对alive_mutations中的每个变异体：
- 测试点测试意图 ≈ 变异体测试目标 → 语义判定=杀死
- 语义判定杀死 → 直接计入AI语义杀死数

> 说明：alive变异体已未被精确覆盖(60%)和范围覆盖(30%)杀死，AI语义判定为独立的第三杀死维度，确认语义相似即直接杀死，无需再叠加不可达的加权得分阈值。

### 计算公式

```
变异杀死率 = (脚本杀死数 + AI语义杀死数) / 变异体总数 × 100%
变异测试得分 = 变异杀死率 × 15分
```

## 五、phase4测试用例对抗（脚本固化+AI判断）

**脚本调用**：
```bash
python {技能目录}/../assets/phase4_adversary.py \
  --testcases {输出目录}/test_cases.md \
  --testpoint {输出目录}/test_point_design.md \
  --output {输出目录}/phase4_adversary.json
```

### 脚本固化部分

| 功能 | 脚本输出 | 说明 |
|-----|---------|------|
| 前置数据锁定 | data_lock | 用例总数、测试点总数 |
| 测试点覆盖率 | coverage | ≥95%阈值 |
| 关键测试点覆盖率 | key_tp_coverage | ≥98%阈值，按场景类型分类统计 |
| 重复用例精确检测 | duplicate.exact_duplicates | 相似度≥95%，自动删除 |
| 质量评分数据准备 | quality_sample | 抽样用例数据 |

### AI判断部分

| 功能 | AI输入 | AI输出 | 说明 |
|-----|-------|-------|------|
| 重复用例语义判断 | duplicate.potential_duplicates | 重复类型判定 | 相似度≥80%，需语义判断 |
| 质量评分 | quality_sample.sample_cases | 步骤清晰性+预期明确性+验证完整性得分 | 抽样评分 |

### 充分性评分

| 维度 | 阈值 | 计算方式 |
|------|------|---------|
| 测试点覆盖率 | ≥95% | 脚本计算 |
| 关键测试点覆盖率 | ≥98% | 脚本计算（按场景类型分类） |

### 关键测试点定义（脚本识别）

| 类型 | 来源列关键词 | 优先级筛选 |
|------|-------------|-----------|
| 特殊场景测试点 | 安全/权限/system | P0/P1 |
| 竞态场景测试点 | 竞态/并发/临界 | P0/P1 |
| 边界值测试点 | 边界/越界/极值 | P0/P1 |
| 数据持久化测试点 | 持久化/存储/写入 | P0/P1 |
| 状态转换测试点 | ASSOC/状态转换/前置依赖 | P0/P1 |
| 异常场景测试点 | 异常恢复/EX- | P0/P1 |
| 组合场景测试点 | 组合/耦合 | P0/P1 |
| 其他P0/P1测试点 | 不属于上述7种 | P0/P1 |

### 补充用例格式

- 编号规则：TC-{NNN}（顺延，禁止TC-ADD）
- 补充方式：batches/batch_supplement.md → merge_batch_mds重新合并
- 验证完整性：预期结果必须包含外部可观测证据
- 内部ID隔离：用例内容使用自然语言，内部ID仅在"关联测试点"列

### 质量检查（AI评分）

| 维度 | 满分 | 评分规则 |
|------|------|---------|
| 步骤清晰性 | 10分 | 清晰→10分，模糊→5分，不可执行→0分 |
| 预期明确性 | 10分 | 明确→10分，含糊→5分，缺失→0分 |
| 验证完整性 | 扣分项 | 仅依赖"接口返回成功"→扣5分 |

**阈值**：平均得分≥18分达标
