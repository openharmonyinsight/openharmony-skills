# 阶段1：需求澄清交互规则（编排器专用）

> **读者**：编排器（主Agent），非执行Agent。本文件定义编排器在Phase1 Agent返回后的交互流程，执行Agent不读取本文件。
> **与phase1_rules.md的区别**：phase1_rules.md是执行Agent的详细规则（Agent自行Read），本文件是编排器的交互逻辑（编排器按需Read）。

## 阶段1确认交互流程

Phase1 Agent 返回摘要后，编排器按以下顺序执行（强制执行，不可跳过）：

**0. 【编排器必做检查】Read requirement_analysis.md 自检部分**
- 若自检结果包含"⚠️"或"未通过" → 必须立即处理，不得进入下一阶段
- 若自检项"输入可控制性"为"⚠️" → 必须追问参数来源，执行答疑流程
- 若自检项"Inner接口过滤"标记"已删除"但§2.1仍有来自InnerApi的参数 → 必须追问并要求重新过滤

**1. 读取 requirement_analysis.md 的"待确认项"表格**
- 若待确认项数 > 0，执行 §1 答疑交互

**2. 使用 AskUserQuestion 确认"需求解析是否正确完整？"**
- 用户选择"需要优化"则 spawn Agent 执行增量修改
- 用户选择"正确，继续"则进入阶段2

## §待确认项答疑交互

### 前置检查

逐条检查待确认项是否命中以下条件，命中则跳过：
- 工程常识可唯一推断答案
- 规格条件逻辑互补可唯一确定
- 文档已标注"已知限制"且已有可测试场景
- 现有规格已足以构造完整测试

跳过后将"用户回答"列填"跳过"，"回答来源"列填"协调器过滤"。

### 分批策略

每批最多10个问题：
1. 待确认项按编号排序
2. 每批取最多10条，构造1次 AskUserQuestion
3. 用户回答后处理结果并写回
4. 每批开始前展示进度提示（"待确认项答疑（第X/Y批）"）

### 问题设计

问题格式：`【来源：{章节}】【影响：{范围}】{待确认内容}（{分析来源}）`

选项末尾统一追加"跳过此项"、"无意义（删除此项）"选项，custom模式默认启用。

### 选项生成规则（核心类型）

| 待确认项类型 | 识别关键词 | 预设选项 |
|------------|----------|---------|
| 非法值行为 | 非法值、无效值、越界 | 静默忽略 / 降级默认值 / 抛出异常 / 跳过 / 无意义（删除此项） |
| 默认值行为 | 默认值、未设置、初始值 | 使用文档值 / 无默认值 / 跳过 / 无意义（删除此项） |
| 性能指标 | 延迟、响应时间、阈值 | 有明确阈值 / 无明确要求 / 跳过 / 无意义（删除此项） |
| 优先级确认 | 优先级、P0、P1 | 高优先级 / 低优先级 / 跳过 / 无意义（删除此项） |
| 其他 | 以上不匹配 | 是 / 否 / 跳过 / 无意义（删除此项） |

**无意义选项处理规则（强制执行）**：
- 每个问题的选项末尾统一追加"无意义（删除此项）"选项
- 用户选择"无意义（删除此项）"后，协调器执行以下操作：
  - 直接从requirement_analysis.md的待确认项表格中删除该条目
  - 不回写"用户回答"和"回答来源"列
  - 在批次进度提示中标注已删除的待确认项编号
- 删除后继续处理剩余待确认项

## 答疑结果处理

用户回答后，协调器直接Edit更新requirement_analysis.md：
1. 回写待确认项表格的"用户回答"和"回答来源"列
2. 根据影响范围回填到主单元场景表（输入条件或预期输出）
3. 更新参数规格表和字段关联图谱（如影响范围包含COND-ID或ASSOC-ID）

## 最终确认

AskUserQuestion："需求解析是否正确完整？"
- 选项：① 正确，继续 ② 需要优化
- 选择"需要优化" → spawn Agent 执行增量修改
