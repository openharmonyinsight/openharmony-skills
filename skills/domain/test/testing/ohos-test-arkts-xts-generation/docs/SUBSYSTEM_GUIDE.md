# 子系统领域知识库新增指引

> **适用对象**: 为 `references/subsystems/` 新增子系统领域知识的开发者
> **版本**: 1.0.0
> **更新日期**: 2026-06-29

---

## 一、知识库架构概览

### 1.1 三层总分结构

```
Layer 0: references/subsystems/_common.md        ← 全局总（跨子系统通用规则，已存在）
         ├── Layer 1: {Subsystem}/_common.md      ← 子系统总（该子系统整体约束）
         │   ├── Layer 2: {Module}.md             ← 模块分（该模块特有约束）
         │   ├── Layer 2: {Module}.md
         │   └── ...
         └── Layer 1: {AnotherSubsystem}/_common.md
             └── ...
```

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **分只含特有规则** | 模块文件（Layer 2）仅包含该模块特有的 API 测试规则，通用规则通过引用父级继承 |
| **引用而非复制** | 子级文件通过引用声明继承父级规则，禁止复制父级内容 |
| **父→子可索引** | 父级文件必须包含子级文件的完整索引 |
| **子→父可追溯** | 子级文件必须声明继承的父级文件 |
| **准确性优先** | 父级文件是权威来源，内容必须准确、引用必须有效 |

### 1.3 各层职责边界

| 层级 | 文件 | 应包含 | 不应包含 |
|------|------|--------|----------|
| **全局总** | `subsystems/_common.md` | 跨子系统通用规则（测试框架、通用断言、@tc 注释规范等） | 特定子系统的 API、流程、权限等 |
| **子系统总** | `{Subsystem}/_common.md` | 该子系统下所有模块共享的规则 + 索引 + 开发阶段定义 + 动静态差异 | 特定模块的 API 测试规则 |
| **模块分** | `{Subsystem}/{Module}.md` | **仅**该模块特有的规则（API 测试场景、错误码、模块特有约束） | 已在 `_common.md` 中定义的通用规则 |

## 二、新增子系统完整流程

### 2.1 流程概览

```
Step 1: 创建目录结构
    ↓
Step 2: 编写子系统总文件（_common.md）
    ↓
Step 3: 编写模块文件（{Module}.md）
    ↓
Step 4: 建立索引关系
    ↓
Step 5: 自检清单验证
```

### 2.2 Step 1: 创建目录结构

```bash
mkdir -p references/subsystems/{SubsystemName}/
```

**命名规范**：
- 子系统名称使用 PascalCase（如 `Camera`、`Image`、`MediaLibrary`）
- 模块文件名与 `.d.ts` 中的 class/interface 名称对应（如 `cameraManager.md` 对应 `class CameraManager`）

### 2.3 Step 2: 编写子系统总文件

创建 `{Subsystem}/_common.md`，必须包含以下章节：

---

#### 必须章节清单

| # | 章节 | 必要性 | 说明 |
|---|------|--------|------|
| 1 | 子系统信息头 | 必须 | 名称、Kit 包、测试路径、版本、更新日期 |
| 2 | API Kit 映射 | 必须 | 导入语句示例 |
| 3 | 测试路径规范 | 必须 | 历史用例、API 文档、API 声明文件、开发指南的路径 |
| 4 | 权限申请约束 | 必须 | 该子系统需要的权限及申请时机 |
| 5 | 开发阶段定义 | 必须 | 该子系统的标准开发流程阶段 |
| 6 | 通用测试规则 | 必须 | 该子系统特有的测试设计规则 |
| 7 | 动静态语法差异 | 必须 | 该子系统特有的动静态差异（如无则注明"遵循通用规范"） |

## 三、反模式（禁止事项）

### 3.1 禁止复制父级内容

**错误做法**：在每个模块文件中完整复制 _common.md 的语法规范、try-catch 要求等。

```markdown
# 错误示例
#### 2.1.5 ArkTS 语法规范要求（强制）
**重要约束**：{Subsystem} 子系统测试必须严格遵循 ArkTS 动态语言语法规范...
1. **类型注解**：...（~30 行详细内容）
2. **字段初始化**：...
...
```

**正确做法**：用一行引用替代。

```markdown
# 正确示例
> **继承自父级**：语法规范、try-catch 结构、@tc 注释模板等通用规则见 [{Subsystem}/_common.md](./_common.md)，以下为本模块特有约束。
```

### 3.2 禁止混淆外部源文件命名

**错误做法**：
```markdown
> - API声明文件: arkts-apis-camera-Flash.md    ← 这是参考文档
```

**正确做法**：
```markdown
> - API声明文件: @ohos.multimedia.camera.d.ts  ← .d.ts 才是声明文件
> - API参考文档: arkts-apis-camera-Flash.md    ← 参考文档单独标注
```

### 3.3 禁止语法模式标注与内容矛盾

**错误做法**：标注为"静态语言语法规范"，但列举的规则是动态语法特征（如 isEmpty()、`| undefined`、`!` 非空断言）。

**正确做法**：
- 如果规范内容是动态语法，标注为"动态语言语法规范"
- 如果规范内容是静态语法，标注为"静态语言语法规范"
- 引用文件必须存在

### 3.4 禁止在模块文件中缺少父级继承声明

**错误做法**：模块文件直接开始写规则，不说明继承关系。

**正确做法**：模块文件头部必须有继承声明。

### 3.5 禁止缺失父→子索引

**错误做法**：_common.md 不列出子模块文件清单。

**正确做法**：_common.md 必须包含模块文件索引表和 API→文件映射表。

## 四、 Checklist 速查表

新增子系统时，按以下顺序完成：

```
□ 1. 创建目录 references/subsystems/{Subsystem}/
□ 2. 创建 _common.md，包含：
    □ 2.1 子系统信息头（名称、Kit包、测试路径）
    □ 2.2 API Kit 映射
    □ 2.3 测试路径规范（历史用例、API文档、声明文件、开发指南）
    □ 2.4 权限申请约束
    □ 2.5 开发阶段定义
    □ 2.6 通用测试设计规则
    □ 2.7 动静态语法差异（转写指南）
    □ 2.8 模块文件索引（.d.ts → 知识库文件 → API参考文档）
    □ 2.9 API 快速查找表
□ 3. 创建各模块文件 {Module}.md，每个包含：
    □ 3.1 模块信息头（.d.ts 声明、API声明文件、API参考文档）
    □ 3.2 父级继承声明（一行引用）
    □ 3.3 API 测试规则（测试场景、错误码、前置条件）
    □ 3.4 模块特有约束（如有）
    □ 3.5 依赖模块声明（如有）
□ 4. 运行自检清单（Step 5）
□ 5. 确认无冗余（不复制父级内容、不横向复制）
```
